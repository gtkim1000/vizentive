# 비젠티브 홈페이지 작업 기록

최종 갱신: 2026-08-26 (모바일 밀도 개선 요청으로 시작해 하루 종일 이어진 세션. **포트폴리오/데이터 월 핀치(두 손가락) 인터랙션을 네 번 재설계 끝에 확정**: 1열↔2열 단순 토글 → 1~3단계 이산 스텝+FLIP 스냅(문턱값 넘기 전엔 반응 없음, 사용자 피드백으로 폐기) → column-width/그리드 auto-fill 기반 "연속처럼 보이는" 방식(실은 브라우저가 항상 꽉 채워 늘리므로 열 개수 바뀌는 순간에만 크기가 변하고 사이 구간은 안 변함, 뒤늦게 발견) → **최종: 열 개수(column-count)는 정수로 고정하고 그 사이 구간엔 `transform:scale()`로 실시간 미리보기(오므리면 계속 작아지며 우측에 여백, 벌리면 계속 커지며 이웃과 겹침)를 보여주다가 정확히 한 열이 바뀔 만큼 크기가 변하는 순간 그 열 개수로 재배열**. 핀치 중인 이미지의 화면 위치를 앵커 카드 기준으로 고정(전체 컨테이너 높이 변화량 기준 보정은 2→1열 등 큰 변화에서 화면이 엉뚱하게 튕기는 부작용으로 폐기, 앵커 카드 1장의 위치만 보는 방식으로 교체 후 드리프트 0 확인). 간격은 매 제스처마다 실측한 비율로 이미지 폭에 비례. 포트폴리오는 1~4열(기본 2, 3열=제목만/4열=이미지만 텍스트 단계적 숨김), 데이터 월은 2~6열(기본 5→여러 차례 조정 끝에 최종 4, 5~6열에서 카테고리 라벨 숨김). 실기기에서 핀치가 안 먹던 문제는 `touch-action` 미설정으로 브라우저 기본 핀치줌과 충돌한 게 원인이었음(도넛 브라우저에 이미 쓰던 `pan-y`로 해결). **포트폴리오 원본보기 오매칭 버그 발견·수정**: 도넛 그룹 계층에 속하지 않는 포트폴리오 전용 항목(좌상단 "비젠티브 브랜드 키비주얼" 등) 클릭 시 엉뚱한 그룹의 첫 항목이 열리던 버그 — 그룹을 못 찾으면 클릭한 항목이 실제로 들어있는 컬렉션을 기준으로 열도록 수정, 전체 카드 스캔 검증. **데이터 월 확대(원본보기 진입) 위치 어긋남을 두 차례 수정**: (1) 모으기 단계에서 카드를 앞으로 튀어나오게 하는 깊이(`--mag-z`)가 확대 단계까지 남아있어 3D 원근 때문에 중앙 이동량이 부풀려지던 문제(확대 시작 시 `--mag-z` 리셋), (2) 핀치 코드가 카드의 `transform-origin`을 `top left`로 바꿔두고 복원을 안 해서, 이후 클릭 시 우하단으로 커지던 문제(스케일 1로 복귀 시 origin도 함께 제거하도록 수정). **데이터 월 썸네일이 "로딩은 됐는데 화면에 안 그려지는" 렌더링 버그를 다섯 차례 시도 끝에 해결** — 처음 네 번(재시도 로직, 동시 요청 6개 제한, `IntersectionObserver` 독립 스크롤 폴백, `will-change` 리페인트 힌트)은 전부 "로딩이 실패했을 것"이라는 검증 안 된 가정 위에서 만든 수정이었고, 매번 "확인했다"고 보고했지만 실제로는 사용자 화면에서 안 고쳐졌음 — 사용자의 직접적 지적("왜 문제없다면서 화면에서는 안보이나?")으로 방향을 바꿔, 사용자의 실제 깨진 브라우저에서 진단 스크립트를 직접 돌려본 결과(`naturalWidth>0`, 즉 이미 다 로딩됨)로 **진짜 원인이 로딩이 아니라 GPU 합성 레이어 페인트 무효화 문제**(3D 카드 스택 특성상 새로 디코딩된 이미지가 레이어에 반영 안 됨, 슬립모드가 카드를 건드리면 그제서야 그려짐)임을 확인 — `img.decode()`로 픽셀이 진짜 준비된 시점을 감지해 그 순간 `display` 토글로 강제 동기 리플로우를 일으키는 방식으로 최종 해결, 사용자 실제 브라우저에서 확인 완료. **기타**: 주요 제작 범위(`.scope-grid`)를 PC 4열/태블릿 3열/모바일 2열로 세분화하고 서체·여백을 줄여 제목·항목이 한 줄에 들어오게 함, "홈페이지 제작" 서비스 카드 신규 추가, "Ways to Work"(요금제) 섹션 전체 삭제. 세션 마지막에 로컬 zip+git bundle과 원격(origin) 태그로 "베타4-모바일최적화" 백업 생성.)

이전 갱신: 2026-08-25 (정전으로 끊긴 세션 재개; 인터랙티브 네트워크 모드를 하루 동안 여러 차례 재설계 끝에 최종 규칙으로 확정 — **"카드간의 위치 이동은 절대 없다. 처음이나 끝이나. 그룹 카드나 말단카드나. 모든 카드는 고유의 궤적을 회전하는 것이고, 선택된 카드로 카메라가 이동하는 것이다"**(사용자 직접 지시, 영구 아키텍처 규칙). 이 규칙이 확정되기까지: 처음엔 클릭한 카드가 중앙(허브 자리)으로 날아가 확대되는 방식이었다가 → 카메라도 함께 움직이도록 추가했다가(카드 이동 + 카메라 이동 동시 진행) → "다른 카드 선택시 카메라 각도가 리셋된다"는 피드백으로 카메라 이동 기능을 제거했다가(카드만 이동하는 원래 방식으로 복귀) → 그래도 "말단 카드 재선택시 카메라는 안 움직이고 카드끼리 자리를 바꾼다"는 재현 및 위 영구 규칙 지시로 **정반대로 재설계**: 이제 모든 카드(그룹·말단 불문)는 선택 여부와 무관하게 항상 자기 궤도를 계속 돈다(위치·크기 절대 불변), 카메라(시야각)만 선택된 카드 쪽을 보도록 매끄럽게 이동한다. 카메라 이동은 CSS 트랜지션이 아니라 매 프레임 JS로 보간해 카드의 실시간 반대회전(빌보드)과 항상 일치하도록 구현(불일치 시 카드가 일그러져 보이는 문제 방지). **선택 카메라 이동 방식은 이후 두 차례 더 발전**: 1차로 "카메라가 계속 따라다니게 해줘, 선택된 카드는 중앙에 정지, 주변은 지구에서 보는 달·태양처럼 움직이게" 요청에 따라 클릭 시점 한 번 조준 방식을 **매 프레임 실시간 재조준하는 지속 추적** 방식으로 바꿨으나, 이 방식(카메라 각도를 매 프레임 강제로 다시 맞추는 것)이 곧바로 새 문제를 낳았다 — "각도를 바꿀 때 바뀐 궤적을 유지하게 해줘. 자꾸 원래로 돌아간다"(드래그해서 각도를 바꿔도 손을 떼는 순간 다시 원래 조준 각도로 스르륵 되돌아감). **2차(최종) 수정**: 카메라 각도를 강제로 맞추는 방식 자체를 버리고, **렌더링 좌표계의 기준점(원점)을 선택된 카드 위치로 옮기는** 방식으로 교체 — 선택된 카드는 이제 항상 "로컬 원점"에 오도록 매 프레임 좌표를 재계산하고, 로컬 원점은 카메라 각도와 무관하게 항상 화면 중앙에 투영되는 기존 불변식(허브가 항상 중앙에 오던 것과 동일 원리)을 그대로 재사용했다. 그 결과 카메라 각도(요/피치)는 순수하게 드래그 조작에 의해서만 바뀌게 되어, 드래그로 바꾼 각도가 더 이상 되돌아가지 않고 그대로 유지된다. 동시에 "선택된 카드가 중앙에서 크게 보이게 해줘" 요청도 반영 — 선택된 카드가 이제 허브와 같은 위치(중앙)를 차지하는 김에 크기도 허브와 같은 확대 배율로 부드럽게 커지도록(사라질 때도 부드럽게 원래 크기로) 만들었다. Playwright로 검증: 포커스된 카드가 화면 중앙에 서브픽셀 단위로 고정되고 실제 크기도 약 1.85배로 커짐을 확인, 드래그 후 1.5초 대기해도 카메라 각도가 드래그 이전 값으로 전혀 되돌아가지 않고(관성에 의한 자연스러운 감속만 있을 뿐) 유지됨을 확인, 이웃 카드는 여전히 화면상 크게 움직여 "달·태양이 도는" 효과가 살아있음을 확인. 또한 "블러 처리 오류를 수정했다고 했는데도 여전히 카드 화면이 흐리다"는 재지적으로 **진짜 원인을 재조사**: 이전에 제거한 CSS 블러 효과와는 별개로, 네트워크 카드가 데이터 월 그리드용 저용량 압축 이미지(`art-XX.webp`)를 쓰고 있었던 것이 원인이었다(동일 해상도지만 압축률이 더 높아 확대 시 흐릿하게 보임) — 도넛 브라우저 카드가 원래 쓰던 고화질 원본 이미지(`original-XX.webp`)로 교체해 선명하게 만들었다. 이에 따라 기존의 "카드가 허브로 날아가 확대", "선택 시 나머지 카드가 뒤로 빠짐(recede)", "그룹 진입시 하부 카드가 허브에서 튀어나오는 스폰 애니메이션", "허브 접기시 카드가 제 자리로 이동" 등 위치를 바꾸던 애니메이션은 전부 제거되고 전부 "불투명도 페이드"로 대체됨 — 부수 효과로 뒤로가기 반복시 그리드가 사라지던 버그의 근본 매커니즘 자체가 사라짐(더 이상 요소별 상태를 이어받는 복잡한 재사용 로직이 없음). 카메라 각도는 이제 사용자가 손으로 맞춘 뒤에도 선택 때문에 리셋되지 않고 유지됨(Playwright로 재검증: 재선택 반복시 카메라 각도가 매번 실제로 변경되고, 카드 위치는 궤도상 정상적인 미세 이동만 있을 뿐 순간이동/교체가 없음을 확인). 그 외 이번 세션에 확정된 것들: 그리드를 여섯 번의 재설계 끝에 "카드와 완전히 분리된 평면 레이어에 그리는 2D 파이프 라인"으로 확정(preserve-3d 안에서 z-index가 무시되는 문제가 최종 원인이었음); 가상 모드 전환 구조를 순차 진행에서 두 장면이 겹쳐 보이는 진짜 크로스페이드로 재구조화; 모드 전환 버튼 아이콘을 3차례 개선 끝에 "3등분 화살표 원" 모양으로 확정; 전환이 평면적이라는 피드백으로 카드에 무작위 3D 텀블링·궤적 편차 추가; 배경(상위 링) 그룹 카드도 클릭 가능하게 만들어 선택 시 현재 그룹을 닫고 곧바로 선택된 그룹으로 진입; 그리드 두께를 여러 차례 요청에 따라 축소(최종 0.85~1.05px); 배경 카드 블러 제거(채도 감소만 유지); 좌상단/우상단 버튼을 콘텐츠 쪽으로 20%가량 이동 + 마우스 오버 시 "상위로 이동"/"가상공간 전환" 풍선 도움말 추가; **"모든 상태 변화는 과정이 보여야 한다"는 사용자 영구 지침을 메모리에 저장**; **선택 카드 크기/구분 표시를 한 차례 더 다듬음**: 포커스를 잃은 카드가 원래 크기로 순간 팍 줄어들던 버그 수정(카드마다 자기 크기를 계속 부드럽게 추적하도록 변경), 포커스가 다른 카드로 전환될 때도 화면이 순간 이동하지 않고 부드럽게 이어지도록 수정, 말단 카드 포커스 시에는 동급(같은 단계) 카드들을 더 이상 흐리게 하지 않고 선명하게 유지, 대신 그룹으로 이어지는 카드에는 항상 보라색 테두리를 넣어 구분(포커스와 무관하게 항상 유지); **그룹 카드(허브) 자체가 자기 안의 멤버가 선택돼도 계속 크게 남아있던 버그 수정** — 지금까지 그룹의 중심 카드(허브)는 항상 고정된 확대 배율로만 그려졌는데, 이제 그 안의 멤버 카드가 선택되면 허브도 함께 원래 크기로 부드럽게 작아지도록 해서, 항상 "선택된 카드 단 하나만" 커 보이도록 통일함; **굵은 테두리 표시 방식을 "선택/중앙" 기준에서 "마우스 오버" 기준으로 전면 교체** — 선택되어 중앙에 있는 카드에는 이제 굵은 테두리를 주지 않고(사실은 예전부터 있던 허브 고유의 은은한 테두리 효과가 "항상 굵은 테두리가 있다"는 오해를 낳았던 것으로 실측 확인), 대신 마우스를 올린(hover) 카드에만 굵고 빛나는 테두리가 순수 CSS로 나타나도록 바꿈; **곧이어 같은 문제가 재발 — 이번엔 진짜 다른 원인**: 카드를 클릭하면 마우스 커서는 그 자리에 그대로 있는데 방금 선택된 카드가 화면 중앙으로 커지면서 이동해오다 보니, 전환이 끝났을 때 커서가 우연히 그 커진 카드 위에 그대로 놓여 있는 경우가 잦았다 — 이게 진짜로 마우스가 그 카드를 hover하고 있는 상태라서 순수 CSS만으로는 "의도적으로 올린 것"과 "우연히 남아있는 것"을 구분할 수 없었다. 선택된(중앙) 카드는 실제 마우스 hover 여부와 무관하게 항상 굵은 테두리 효과에서 제외되도록 예외 처리를 추가해 완전히 해결; **세 가지 추가 수정**: (1) 그룹 카드의 가느다란 테두리를 요청대로 완전히 제거; (2) 가상공간2 첫 진입 시 카드들이 기울어진 채 움직이다 갑자기 정면을 보던 문제를 CSS 트랜스폼 함수 목록 불일치로 수정했으나 **재보고됨(여전히 있음) → 진짜 원인을 다시 찾음**: 아래 참고; (3) "하부 카드들이 그룹 카드로 모여 없어진 뒤 그룹 카드가 제자리를 찾아가는" 접기 애니메이션이 이전 재설계 때 사라진 것을 확인하고 복원 — "카드 위치 이동 금지" 영구 규칙에 대한 명시적 예외로, 없어질 하부 카드가 자신을 흡수할 그룹 카드 쪽으로 모여드는 것으로 한정. **뒤이어 (2)의 진짜 원인 발견**: 화면 회전을 담당하는 컨테이너 자체의 CSS 회전값이 첫 진입 시 한 번도 초기화되지 않고 있었음(드래그를 하거나 1.2초 무입력 후에야 처음 설정됨) — 그 전까지는 각 카드가 "컨테이너가 이만큼 돌아가 있을 것"이라고 가정하고 계산한 역회전이 실제로는 존재하지 않는 회전을 상쇄하려 해서 전부 어긋나 보였고, 1.2초 뒤 컨테이너 회전값이 처음 설정되는 순간 전부 갑자기 맞아떨어지며 "정면을 향하는" 스냅이 발생한 것 — 카드 렌더링을 담당하는 함수가 매번 컨테이너의 회전값도 함께 맞춰 쓰도록 해서 다시는 어긋날 수 없게 근본적으로 고침. **그룹 카드 선택 시 하부가 펼쳐지는 과정도 함께 복원**: 아래 새 항목 참고; **레벨 전환 애니메이션을 "매번 다 지우고 새로 그리기"에서 "살아남는 카드는 진짜로 같은 화면 요소를 재사용해 부드럽게 이동"하는 방식으로 전면 재설계** — 그룹 접기 시 방금까지 중심이었던 카드가 실제로 다른 그룹들 사이 제자리로 이동하는 과정이 눈에 보이게 됐고, 다른 그룹으로 옮겨갈 때도 남아있는 상위 카드들이 사라졌다 다시 나타나지 않고 그 자리에서 매끄럽게 재배치됨 — 아래 새 항목 참고; **홈페이지 첫 진입 시 가상 공간 모드(도넛 브라우저/인터랙티브 네트워크)를 랜덤하게 선택하도록 변경** — 새로고침마다 둘 중 하나가 무작위로 먼저 보이며, 네트워크 모드가 첫 화면으로 뜨는 경우도 새로 검증해 문제없음을 확인함; **곧이어 "그리드가 깨진다" 재보고 → 새 경로가 처음으로 밟은 미검증 코드 경로에서 카드/연결선 초기 투명도 설정이 누락돼 있던 버그를 발견해 수정**했으나, 이 검증은 "페이지를 새로 열 때"만 반복 테스트한 것이었고 **사용자가 직접 "띄우고 나서 전환할 때 깨지는 거다, 그냥 띄우기만 하면 안 깨진다"고 정확한 재현 경로를 짚어줘서 재조사** → **진짜 원인**: 가상 모드를 껐다 켤 때마다(토글 버튼) 화면을 다시 그리는 두 지점이 "지금 화면에 뭐가 떠 있는지" 스냅샷을 넘기지 않아 옛 카드·연결선을 정리하지 않고 매번 새 세트를 덧붙이기만 해서, 전환을 반복할수록 화면에 안 보이게 얼어붙은 유령 카드/연결선이 계속 쌓이던 것(왕복 1회만으로 실측 카드 24개 vs 실제 추적 8개) — 두 지점 모두 그룹 진입/뒤로가기와 동일하게 스냅샷을 넘기도록 수정해 근본 해결, 왕복 3회·계층 2단계 깊이에서의 왕복까지 반복 검증해 유령 요소 0개 확인)

## 도넛 브라우저 동작

- 마우스 드래그 및 모바일 스와이프로 회전한다.
- 전면이 아닌 이미지를 선택하면 전면으로만 이동한다.
- 최전면 대표 이미지를 선택하면 하부 이미지로 들어간다.
- 최전면 하부 이미지를 선택하면 고해상도 원본 보기로 들어간다.
- 최전면 이미지는 조금 더 크게 표시한다.
- 후면 이미지도 흐리게 만들지 않고 최대한 선명하게 표시한다.
- 대표 이미지 설명은 대분류 상태에서만 표시한다.
- **최상위(대분류)와 하위(하위그룹/작품) 단계의 카드 크기·움직임은 완전히 동일하다(2026-08-23 통일)**: 원래 `layoutTorus()`의 카드 크기 공식이 `torusMode==='groups'`일 때(`.66+depth*.4`, depth에 선형 비례)와 그 외 단계일 때(`.72+depth^8*.34`, 대부분 구간에서 거의 평평하다가 맨 앞에서만 급격히 커짐)로 서로 달랐다 — 이 때문에 하위 단계에서는 양 끝(옆면) 카드가 대분류 단계보다 눈에 띄게 작아 보였고, 사용자는 이를 "출렁임이 더 많다"고 체감했다(실제로는 파도 진폭 자체가 다른 게 아니라 카드가 작아서 상대적으로 더 흔들려 보이는 것이었다 — `waveY`/`baseY`/`emphasis` 등 다른 움직임 공식은 애초부터 모드 무관 공통이었음). 사용자 요청으로 하위 단계 공식(`.72+depth^8*.34`)으로 완전히 통일 — 이제 `torusMode` 조건 분기 자체가 없다. Playwright로 depth→scale 관계를 두 모드에서 각각 재구성해 오차 0으로 완전히 동일함을 확인.
- **회전 속도 연동 반경 확대 + 카드 확대, 최종 확정 동작(2026-08-23)**: 빠르게 드래그해서 돌릴수록 ① 카드들 사이의 **가로 간격**(원심력처럼, `rx`만)이 최대 **200%**(`torusSpinRadiusBoostMax=1`)까지 벌어지고, ② 카드 자체의 **확대(스케일)**도 별도로 최대 **125%**(`torusSpinScaleBoostMax=.25`, `.1`→`.2`→`.3`→`.25`로 재조정, `compositeScale`에 곱함)까지 커진다 — 이 둘은 서로 독립된 상태값(`torusRadiusBoost`/`torusScaleBoost`)이며 `layoutTorus()`에서 각각 적용된다. **단, 깊이(`rz`)는 절대 건드리지 않는다** — 한때 `rz`도 같이 키운 적이 있었는데, 카드가 카메라에 가까워지면서 고정된 CSS `perspective` 때문에 원근 효과로 카드가 화면을 덮을 만큼 확대되어 보이는 부작용이 있어 완전히 되돌렸다(스케일은 오직 명시적 `compositeScale` 곱셈으로만 조절, `rz`는 항상 기본값 고정). Playwright 실측: 가로 반경 배율 ~2.02배, 카드 스케일 배율 ~1.11배로 목표치와 정확히 일치, 부작용 없이 깔끔하게 동작 확인. 두 효과 모두 속도→목표값 민감도(`torusSpinRadiusBoostScale=6.25`, 공유)와 느린 복귀(각각 `torusSpinRadiusBoostFallRate`/`torusSpinScaleBoostFallRate=.01`, 관성 감쇠와 분리)를 따른다. 클릭 선택·카테고리 스냅 등 회전이 멈추는 모든 상황에서 동일하게 적용. **다시 조정 요청이 오면 각 최대치(`torusSpinRadiusBoostMax`/`torusSpinScaleBoostMax`)와 복귀 속도만 건드리고, `rz`는 절대 손대지 말 것.**

- **회전 관성(손 뗀 뒤 서서히 멈추는 것) 감쇠 속도(2026-08-23, 두 차례 조정)**: `spatialFrame()`의 `torusVelocity*=RATE`(프레임당 감쇠율)를 원래 `.94`에서 `.9695`(1차, "두 배 더 느리게")를 거쳐 최종 **`.9846`**(2차, "관성이 좀 더 오래 지속되도록, 2배 정도")로 변경 — 매번 "N배 느리게"는 `기존값**(1/N)`(= `sqrt`, N=2일 때)로 계산해서 "지수적으로 반으로 줄어드는 데 걸리는 시간(half-life)"이 정확히 N배가 되도록 함(`.94`→`.9695`→`.9846` 각 단계가 half-life 2배씩). Playwright로 `.torus-card.front`가 바뀌는 시점을 추적해 관성 지속 시간이 이전(~2.8초)보다 늘어난 것(~5.9초)을 실측 확인. 이 상수는 위 반경/확대 효과(`torusSpinRadiusBoostScale`이 이 속도값을 그대로 참조)와도 연결되어 있어, 관성이 느려지면 반경·확대가 커져 있는 시간도 자연히 함께 길어짐 — 의도된 상호작용이며 별도 보정 불필요. 다시 "더 오래/짧게 돈다"는 요청이 오면 이 감쇠율 하나만 `기존값**(1/N)` 또는 `기존값**N`으로 재계산(절대 가까운 소수점을 감으로 넣지 말 것), 관성 정지 임계값(`.00002`)은 그대로 둔다.
- **가상 공간 모드 전환 버튼(2026-08-23 추가, 스캐폴드만)**: 우상단에 항상 표시되는 원형 아이콘 버튼(`#torusModeToggle`, 글자 `⟳`)을 추가 — 좌상단의 `torusBack`(하위 그룹 진입 시에만 보임)과 달리 모드와 무관하게 **항상** 떠 있다. 클릭하면 `spatialModes=['torus','placeholder']` 배열을 순환하며 `#spatialIntro`의 `data-spatial-mode` 속성을 바꾼다(`torus`↔`placeholder`). `placeholder`가 되면 CSS로 `.torus-shell`/`.hologram`/`.torus-back`/`.scene-counter`를 숨기고 `.spatial-placeholder`("모드 2 준비 중")를 대신 보여준다 — **아직 실제 두 번째 가상 모드는 디자인되지 않았고, 사용자가 명시적으로 "버튼·전환 구조만 먼저" 만들라고 요청**해서 지금은 자리만 잡아둔 상태. 실제 두 번째 모드(어떤 3D/공간형 레이아웃일지)는 다음 요청에서 구체화 예정이며, 그때 `spatialModes` 배열에 값 하나 추가 + 해당 모드 렌더링 함수 연결로 확장하면 됨(모드 개수는 향후 더 늘어날 수 있음, 배열 기반이라 확장 용이). **자동 전환 모드(도넛을 너무 빠르게 돌리면 회전이 "터져서" 다른 모드로 자동 재조합되는 연출)는 사용자가 명시적으로 "아직 코딩하지 말아달라"고 해서 미구현** — 나중에 요청 오면 그때 설계.
- 버튼 위치는 반드시 **고정 px로 헤더(78px, 모바일 640px 이하는 70px)를 기준으로 여백을 둬야 한다** — 처음에 `top:4%` 같은 퍼센트로 배치했다가 짧은 섹션 높이에서 실제 계산값이 헤더 아래로 못 내려가 고정 헤더(`z-index:80`)가 클릭을 가로채는 문제가 있었음(Playwright로 클릭 타임아웃 발생시켜 발견). `hologram`은 `pointer-events:none`이라 시각적으로 살짝 겹쳐도 클릭은 안 막히지만, 실제 클릭 가능한 `.header`와는 항상 좌표를 띄워야 함.

## 가상 공간 모드 2 추가 개선 — 다중 링 공존 + 그리드 상시 노출 + 클러스터링/전환 버그 수정(2026-08-23, 같은 날 후속 라운드)

태양계 모델 확정 직후 실사용 피드백으로 4가지를 더 고쳤다: (1) 최상위(허브 없음)에서 카드 사이 연결선(그리드)이 아예 안 보이던 것을 상시 노출로, (2) 그룹 카드를 클릭하면 화면이 하위 카드로만 완전히 대체되던 것을 상위/하위가 함께 보이는 방식으로, (3) 가상 모드를 여러 번 왕복하면 네트워크 카드가 전부 화면 정중앙으로 뭉쳐버리던 버그, (4) 모드 전환 시 카드가 흩어졌다가 다시 나타나는 과정이 안 보이고 "퍽" 하고 순간 이동하듯 보이던 버그.

- **다중 링(계층 공존) 구조로 전면 재설계**: 기존엔 `networkMode`/`networkItems` 단일 레벨만 렌더링했지만, 이제 `networkStack`(배열, 0번=최상위 groups, 마지막=현재 보고 있는 레벨)을 도입해 **스택에 쌓인 모든 레벨을 동시에 렌더링**한다. 가장 안쪽 링(ring 0, 방금 진입한 레벨의 자식들)은 원래대로 크고 뚜렷하게, 그 바깥 링(ring 1=부모 레벨, ring 2=조부모 레벨)은 반지름을 더 크게(`NETWORK_RING_GAP=.75`배씩 누적), 크기(`nodeScale`, 링당 -16%, 최소 55%)와 투명도(`nodeOpacity`, 링당 -22%, 최소 45%)를 낮춰 "배경으로 물러난 상위 카드"처럼 보이게 한다. 궤도 공전 속도도 바깥 링일수록 느려진다(`NETWORK_RING_SPEED_FALL`) — 큰 구조일수록 천천히 도는 것이 우주 비유에 더 맞는다는 판단. **바깥 링 카드는 클릭 불가**(`interactive:false`, `<button>` 대신 `<div>`로 렌더링 + CSS `pointer-events:none`)로 만들어, "장식으로만 공존하고 실제 조작은 현재 레벨에서만" 하는 단순한 규칙으로 정리 — 배경 카드를 클릭해 그 레벨로 점프하는 기능은 이번엔 넣지 않음(필요하면 후속 요청으로).
- **그리드(연결선)를 항상 렌더링** — 2026-08-25 재설계: 처음엔 모든 링의 모든 카드가 원점으로 연결선을 그리게 했으나 실사용 피드백("그리드 형태가 이상하다, 잘 안 보인다")으로 **링(궤도) 단위의 원형 그리드**로 교체했다. 상세는 아래 "2026-08-25 추가 개선" 절 참고.
- **back(뒤로 가기)는 스택 pop으로 단순화**: 예전엔 `networkGroupIndex`+`torusGroups[...].direct` 조합으로 부모를 역산하는 별도 로직이 있었는데, 스택 모델에서는 그냥 `networkStack.pop()`만 하면 자동으로 정확한 부모 레벨(및 그 부모의 등급별 분기: 하위그룹이 있었는지 없었는지)로 복원된다 — 로직이 크게 단순해짐.
- **클릭 인덱스 처리 주의사항(구현 중 발견)**: 여러 링을 하나의 `networkNodes` 배열로 합치면서, "전역 배열 인덱스"와 "현재 레벨(`networkItems`) 안에서의 인덱스"가 더 이상 같지 않게 됐다(링 0이 배열 뒤쪽에 push되므로). 리프 카드를 두 번째 클릭했을 때 `openModal(index, networkItems)`을 호출하던 부분이 잘못된 인덱스를 넘길 뻔한 버그라 각 노드에 `itemIndex`(자기 레벨의 원본 배열에서의 위치)를 별도로 저장해 그걸 넘기도록 수정 — **여러 소스를 하나의 평면 배열로 합칠 때는 "전역 위치"와 "원래 그룹 내 위치"를 반드시 별개 필드로 유지할 것**, 하나로 착각하면 조용히 엉뚱한 아이템이 열린다.

### 버그: 가상 모드를 여러 번 왕복하면 네트워크 카드가 화면 정중앙으로 뭉침
원인: `.network-shell`은 CSS로 `display:none`(비활성 모드일 때) 처리되는데, `transitionSpatialMode()`가 **모드가 실제로 바뀌기 전에** "정리 차원에서" 네트워크를 항상 다시 빌드하고 있었다(`if(networkInitialized){...rebuild...}`, 조건에 목표 모드 여부가 없었음). 도넛 모드에 있다가 네트워크로 넘어가는 순간에는 이 재빌드가 **네트워크 셸이 아직 숨겨진(0×0 크기) 상태에서** 실행되어, 화면 크기를 재는 `measureNetwork()`가 `getBoundingClientRect()`로 0을 읽어 궤도 반지름 `r=0`이 되고, 결과적으로 모든 카드의 좌표가 `(0,0,0)`(정중앙)으로 붕괴했다. 이후 화면이 실제로 네트워크로 바뀌어도 이미 반지름 0으로 계산된 좌표를 그대로 쓰니 카드가 전부 중앙에 뭉쳐 보인다. **수정**: 재빌드 조건을 `networkInitialized && 현재모드==='network'`(즉 "지금 네트워크를 떠나는 참이라 화면이 아직 보이는 시점")로 한정 — 숨겨진 상태에서는 절대 재측정하지 않는다. 추가로 `measureNetwork()` 자체에도 방어 코드를 넣어, 측정값이 0이면 마지막으로 유효했던 반지름(`lastNetworkRadius`)을 그대로 쓰도록 해 비슷한 계열의 버그가 재발해도 카드가 중앙에 뭉치는 대신 이전 크기를 유지하게 안전장치를 걸었다. **교훈**: `display:none`인 요소의 크기를 재는 코드는 "그 요소가 진짜 화면에 보이는 시점"에만 실행되도록 호출 시점을 엄격히 통제해야 한다 — 안 보이는 동안 측정하면 0이 나오는 게 당연한데, 그 0이 다른 계산(궤도 반지름 등)에 조용히 스며들면 훨씬 나중에야 "카드가 뭉친다"는 형태로 튀어나와 원인 추적이 어렵다.

### 버그: 전환 시 카드가 흩어졌다가 나타나는 과정이 안 보이고 "퍽" 하고 순간 이동
원인: `scatterIn` 계열 함수들이 "① 모든 카드를 흩어진 위치로 순간 이동(트랜지션 없음) → ② 컨테이너 리플로우 강제 → ③ 곧바로 같은 동기 실행 흐름 안에서 트랜지션을 건 자연 위치로 재이동"의 순서를 쓰고 있었는데, 강제 리플로우 직후 **같은 틱(tick) 안에서** 곧바로 스타일을 다시 바꾸면, 브라우저가 ①과 ③ 사이의 "흩어진 상태"를 한 번도 실제로 페인트하지 않고 두 스타일 변경을 하나의 프레임으로 합쳐버리는 경우가 있다 — 그 결과 트랜지션이 "재생"되는 게 아니라 최종 상태로 즉시 점프한 것처럼 보인다. **수정**: 리플로우 이후 ③(트랜지션 적용 + 최종 위치 지정)을 `requestAnimationFrame`을 **두 번 중첩**해서(`requestAnimationFrame(()=>requestAnimationFrame(()=>{...}))`) 미뤘다 — 브라우저가 반드시 "흩어진 상태"를 한 프레임 실제로 그리고 난 다음에야 최종 상태로의 전환이 시작되도록 강제하는, 잘 알려진 안정적인 패턴. Playwright로 전환 중간 지점(스크린샷 여러 장)을 찍어 카드가 작고 흐릿하게 시작해서 점점 커지고 선명해지는 중간 프레임이 실제로 보이는 것을 확인(수정 전에는 이 검증 방법 자체가 없어 놓쳤던 부분 — `style.transform` 값을 JS로 읽는 것만으로는 이 버그를 발견할 수 없고, 반드시 화면을 실제로 캡처해서 눈으로 확인해야 한다는 것도 이번에 배움).

### 버그: 리프 카드를 포커스(1차 클릭)한 뒤 같은 카드를 다시 눌러도 뷰어가 안 열림
다중 링 도입 후 스트레스 테스트 중 발견(다중 링이 아니어도 이론상 존재했을 오래된 버그): 포커스된(화면 중앙으로 확대된) 카드는 `applyNetworkBillboard()`의 매 프레임 갱신 대상에서 제외되는데(`entering` 클래스가 있으면 스킵), 이때 `z-index`도 그 카드가 마지막으로 가졌던 값에 **그대로 멈춘 채** 남는다. 반면 나머지(계속 공전 중인) 카드들은 매 프레임 새로 순위를 매겨 z-index가 계속 바뀐다 — 시간이 조금만 지나면 공전 중인 다른 카드가 우연히 더 높은 z-index를 받아, 화면 정중앙(포커스된 카드가 있는 바로 그 자리)을 지나가면서 포커스된 카드를 완전히 가려버린다. 그 상태에서 "같은 카드"를 다시 클릭한 사용자의 클릭은 실제로는 위를 덮은 다른(공전 중인) 카드를 클릭한 게 되어, 뷰어가 열리는 대신 포커스가 엉뚱한 카드로 옮겨간다. **수정**: 포커스 시작 시 그 카드에 `z-index:999`를 명시적으로 고정(다른 카드가 절대 못 덮도록)하고, 동시에 나머지 형제 카드들에는 `pointer-events:none`을 걸어(포커스 해제 시 복원) 설령 시각적으로 겹치더라도 클릭을 가로채지 못하게 이중으로 막았다. Playwright로 900ms 대기(공전이 한 바퀴 가까이 돌 만큼 충분히 긴 시간) 후에도 4라운드 연속 정상적으로 뷰어가 열리는 것을 확인.

### 2026-08-25 추가 개선 — 그리드 재설계 + 그룹/현재 레벨 시각적 차별화 + 선택 시 흐려지며 뒤로 빠짐

정전으로 끊긴 세션을 재개, 위 라운드(2026-08-23)의 실사용 피드백 4가지를 추가로 반영했다.

- **그리드를 "카메라를 항상 정면으로 보는 궤도 링"으로 교체**: 처음엔 각 링을 실제 3D 궤도 평면에 눕혀서(`rotateX(90deg)`) 렌더링했는데, 기본 카메라 피치(`-8°`)가 거의 0에 가까워 원이 옆에서 본 것처럼 거의 실선 두께로 찌그러져 사실상 안 보였다(`그리드가 잘 안 보인다` 원인). **수정**: 카드처럼 매 프레임 `rotateY(-yaw) rotateX(-pitch)`로 카메라를 항상 정면으로 보게(빌보드) 만들어, 레이더 화면 같은 뚜렷한 동심원으로 항상 보이게 했다(`renderNetworkOrbits()`+`applyNetworkBillboard()`). 최상위(허브 없음)에도 링 0 궤도 원 하나가 항상 존재해 "그리드 상시 노출" 요구를 그대로 만족. 허브→자식 스포크 선(`.network-edge`)은 원래 의도대로 링 0(현재 레벨의 자식)에만, 허브가 있을 때만 그린다 — 예전에 모든 링이 원점으로 선을 그리던 방식(관계없는 조상 카드들이 현재 허브로 선이 모이는 모양)이 "그리드 형태가 이상하다"의 원인이었다.
- **그룹(상위 링) vs 현재 레벨(링 0) 크기 차이 확대**: `NETWORK_RING_GAP`(링간 반지름 배율) `.75`→`1.1`, `NETWORK_RING_SCALE_FALL`(링당 축소율) `.16`→`.3`(바닥 `.42`), `NETWORK_RING_OPACITY_FALL`(링당 투명도 감소) `.22`→`.38`(바닥 `.28`)로 대폭 확대. 추가로 링>0 카드에는 인라인 `filter:saturate() blur()`(링 번호에 비례)를 걸어 "배경으로 물러난" 느낌을 스케일·투명도와 함께 이중으로 강화 — "그룹과 그룹 아닌 것이 섞여 구분이 안 된다" 해결.
- **카드 선택 시 나머지는 사라지지 않고 흐려지며 뒤로 빠짐**: 리프 1차 클릭(`focusNetworkNode()`)과 그룹 드릴다운(`enterNetworkNode()`) 모두 기존엔 선택 안 된 카드를 `opacity:0`으로 완전히 숨겼는데("선택한 카드만 덩그러니 보인다" 원인), 이제 `NETWORK_FOCUS_DIM_OPACITY=.16`으로 흐리게만 만들고, 동시에 `applyNetworkBillboard()`에서 선택 안 된 카드(허브 포함)에 `NETWORK_FOCUS_RECEDE_SCALE=.7`·`NETWORK_FOCUS_RECEDE_Z=-190`(카메라에서 멀어지는 방향, `.torus-card.diving`과 동일 부호 규약)을 적용해 실제로 뒤로 물러나는 것처럼 보이게 했다. 선택된 카드는 기존대로 `z-index:999`+허브 스케일로 확 앞으로. `clearNetworkFocus()`가 이전엔 방금 포커스 해제된 카드 하나만 복원하던 비대칭 버그도 겸사겸사 수정(이제 전체 노드/엣지/허브를 base 상태로 복원) — `restoreNetworkView()`는 이제 그냥 `clearNetworkFocus()`의 별칭.
- **검증 중 발견한 셀렉터 함정**: 다중 링 렌더링 이후 `.network-node[data-index]`는 더 이상 "클릭 가능한 카드만"을 뜻하지 않는다 — 배경(링>0, `<div class="network-node--bg">`) 카드도 `data-index`는 그대로 갖고 있고 단지 `<button>`이 아니고 CSS `pointer-events:none`일 뿐이다. 클릭 가능한 카드만 골라야 하면 `button.network-node[data-index]`로 질의해야 한다 — 처음 Playwright 검증에서 이걸 놓쳐 "중심 카드 재클릭 시 원본 보기가 안 열린다"는 가짜 회귀로 오인했었다(실제로는 검증 스크립트가 클릭 불가능한 배경 카드를 잘못 골라서 발생한 스크립트 버그, 실제 사이트 동작은 정상이었음). Claude 메모리 `torus-network-mode`에도 이 정정을 기록해 둠.
- 위 3가지("그룹1 클릭시 상위/하위 공존", "전환 반복 시 중앙 뭉침", "전환 시 퍽 나타남") 자체는 2026-08-23 라운드에서 이미 근본 수정되어 있었고, 이번 라운드에서도 Playwright로 재검증해 여전히 정상 동작함을 확인했다(전환 3회 반복 후에도 카드 퍼짐 폭 ~720×360px로 중앙 뭉침 없음, 흩어짐 중간 프레임이 스크린샷에 실제로 보임).

### 버그(재발): "전환 시 퍽 나타남"이 실제로는 도넛→네트워크 방향의 **두 번째 이후 진입**에서만 여전히 남아있었음
위 검증 직후 사용자가 "그런 과정이 안 보이고 갑자기 전부 나타난다... 두 번 해서 원래대로 돌아가 버린다"고 재보고 — 재검증 방법의 허점이 원인이었다. **진짜 원인**: `applySpatialMode()`가 네트워크 모드 진입 시 부르는 `ensureNetworkBuilt()`가 "**최초 1회만** 재구성"하도록 되어 있었다 — 두 번째 이후 도넛→네트워크 전환에서는 지난번 나갈 때 화면 밖으로 흩어진 채 멈춰있던 낡은 좌표를 "자연 위치"로 착각해 그 방향으로 애니메이션했다. 즉 실제 복귀 애니메이션은 화면 밖 어딘가에서 벌어져 안 보였고, 전환이 끝나 렌더 루프가 재개되는 순간(`applyNetworkBillboard()`가 매 프레임 궤도 데이터에서 위치를 다시 계산) 카드가 올바른 자리로 한 프레임 만에 "순간 스냅"됐다 — 이게 "퍽 나타남"의 정체. 애니메이션이 멈춘 것처럼 보여 사용자가 혼란스러워 다시 클릭하면, 이번엔 정상 작동하는 네트워크→도넛 방향이 걸려 "두 번 눌러서 원래대로 돌아간" 것처럼 보였다 — 두 신고가 같은 원인. **수정**: `ensureNetworkBuilt()`가 매번(최초 포함) `syncNetworkCurrent()`로 재동기화하도록 변경 — 이 함수가 불릴 시점엔 이미 CSS 모드가 전환되어 셸이 보이는 상태이므로(`.network-shell{display:block}` 적용 후), "숨겨진 0×0 상태에서 재측정하면 중앙에 뭉친다"는 예전 버그를 다시 불러오지 않는다. **검증 방법의 교훈**: 이전 라운드 검증은 network→torus 방향의 중간 프레임과 torus→network 방향의 "완전 정착 후" 상태만 캡처해서 이 비대칭 버그를 놓쳤다 — 토글의 양방향 모두, 그리고 최초 1회가 아니라 3회 이상 반복한 뒤의 중간 프레임을 반드시 캡처해야 한다. 재수정 후 3번째 토글(도넛→네트워크 재진입)의 150/270/570ms 중간 프레임을 캡처해 570ms 시점에 이미 정상적인 카드 배치가 보이는 것으로 확인.

### 버그(더 심각한 재발): "전환이 제대로 안 된다, 자꾸 원래대로 돌아간다" — 회전 관성이 전환 시 초기화되지 않음
위 수정 직후 사용자가 다시 "전환이 잘 안 되고 자꾸 원래대로 돌아간다"고 보고 — 이번엔 완전히 다른, 더 심각한 원인이었다. `transitionSpatialMode()`가 드래그 플래그(`networkDragging` 등)는 초기화하면서도 **회전 관성 속도값(`torusVelocity`/`networkVelocityYaw`/`networkVelocityPitch`)은 전혀 초기화하지 않았다**. 빠르게 돌리는 것 자체가 전환을 유발하는 조건(수동 클릭 도중이든, 최고 속도 자동전환이든)이라 이 잔여 속도가 전환 후에도 그대로 남고, 특히 네트워크 쪽 속도는 도넛 모드에 있는 동안 전혀 감쇠되지 않는다(`networkFrame()` 자체가 안 돌기 때문). 그 결과 네트워크 모드로 다시 들어가는 순간, 그 첫 프레임의 최고속도 자동전환 검사가 여전히 임계값을 넘는 낡은 속도값을 보고 **즉시 다시 튕겨나갔다** — 그리고 이 값을 소비/감쇠시킬 방법이 전혀 없었기 때문에, 한 번 발동되면 페이지를 새로고침하기 전까진 네트워크 모드에 사실상 영구히 못 들어가는 상태가 됐다. **수정**: `transitionSpatialMode()` 맨 앞에서 세 속도값을 모두 0으로 초기화 — 드래그 플래그를 초기화하는 것과 같은 자리에 나란히 추가. Playwright로 속도를 임계값 이상(20, 임계값 16)으로 인위 주입한 뒤 자동전환이 발동해 속도가 즉시 0으로 리셋됨을 확인하고, 그 직후 수동으로 다시 네트워크 모드에 진입해 2초 이상 추가로 지켜봐도 튕겨나가지 않고 안정적으로 유지됨을 확인했다(이전엔 이 시점에서 즉시 재발동했을 것). **교훈**: "이 상호작용/세션은 끝났다, 깨끗하게 시작한다"는 의미의 전환 지점은 관련된 모든 관성/속도 상태를 초기화해야 한다 — 플래그만 지우고 숫자형 관성값은 그대로 두면 그 자체로는 문제없어 보여도, 별개의 임계값 기반 자동 트리거와 결합해 스스로 반복되는 루프가 될 수 있다.

### 버그(세 번째 재발): 도넛 쪽에도 똑같은 "낡은 좌표를 자연 위치로 착각" 버그가 그대로 남아있었음
사용자가 다시 "중간 과정이 자꾸 연계가 안 되고 끊깁니다... 갑자기 나타나거나 합니다"라고 보고. 이번엔 **네트워크→도넛 방향(재진입)에 똑같은 병이 처음부터 안 고쳐진 채 남아있었다** — `applySpatialMode()`에 애초에 `mode==='torus'` 분기 자체가 없어서, 도넛으로 돌아올 때 `layoutTorus()`를 새로 부르는 코드가 전혀 없었다. 도넛이 화면 밖에 있는 동안(`spatialFrame()`이 `!isOnScreen(torusShell)`이면 `layoutTorus()`를 건너뜀) 카드의 `.style.transform`은 지난번 나갈 때 흩어진 좌표에 그대로 얼어붙어 있었고, `scatterInTorus()`가 이걸 "자연 위치"로 읽어 그쪽으로 애니메이션했다 — 네트워크 쪽과 완전히 같은 원인. **수정**: `applySpatialMode()`에 else 분기 추가, 도넛 진입 시 `torusMetrics=null;layoutTorus();noteTorusInput()`. **수정 중 새 버그 유발 후 즉시 발견·수정**: 이 코드를 조건 없이 넣었더니 페이지 부팅 시 최초 1회 자동 호출되는 `applySpatialMode()`(스크립트 맨 아래, `torusMetrics` 등 여러 `let` 선언보다 코드상 **앞쪽**에서 실행됨)에서 아직 초기화 안 된 변수를 참조해 `ReferenceError`가 터지고 그 뒤 스크립트 전체가 조용히 멈춰버렸다(Playwright 스모크 테스트로 즉시 발견) — `torusScene.children.length`가 있을 때만(부팅 시점엔 아직 카드가 없음) 실행하도록 가드를 추가해 해결. **교훈**: 여러 호출 지점을 가진 함수에 "새로 리빌드" 코드를 추가할 때는 그 함수가 불리는 **모든** 지점의 타이밍(특히 부팅/초기화 시점 호출)을 다 확인해야 한다.

### 그리드 — 네 번의 재설계 끝에 "화면 2D 좌표로 그리는 파이프 라인"으로 확정
1차(궤도 원만, "원으로 나온다") → 2차(원+십자선, "고정이야, 연결 안 됨") → 3차(카드마다 원점으로 이어지는 실시간 연결선, 3D 회전으로 위치 지정 + z-index를 소유 카드와 동률로) — 이 3차에서 가시성 문제(z-index로 항상 카드에 가려짐)는 해결됐지만, 곧바로 **"모드 전환할 때 연동 안 됨"**(전환 애니메이션은 카드 translate3d만 다루는데 선은 항상 원점(0,0,0)에 고정이라 흩어짐에 반응하지 않음), **"회전하면 굵어졌다 가늘어짐"**(선을 진짜 3D 평면으로 회전시키다 보니 카메라 각도에 따라 원근 압축으로 두께가 실제로 변함), **"그리드가 카드 위에 옴"**(소유 카드와 z-index를 맞춰서 생긴 부작용) 세 가지가 연쇄로 드러났다. **네 번째(최종)**: 세 문제 모두 "선을 3D 공간에서 실제로 회전시킨다"는 표현 방식 하나에서 나온 증상이라는 걸 깨닫고, 표현 자체를 **순수 2D 화면 좌표계**로 바꿨다 — 매 프레임 카메라 회전 행렬로 카드의 픽셀 위치를 투영(CSS `perspective`와 동일한 공식으로 직접 계산)해 화면상의 실제 거리·각도를 구하고, 선은 `rotateY/rotateZ`(3D) 대신 평범한 `rotate(deg)`(2D)로만 그린다. 2D 아핀 회전은 원리상 두께가 절대 안 변하므로 "굵기 요동" 문제가 근본적으로 사라지고(카메라 회전 전후 `getComputedStyle().height`가 4px→4px로 완전 동일함을 확인 — `getBoundingClientRect().height`로는 검증 불가, 회전된 2D 박스는 실제 두께가 그대로여도 축 정렬 바운딩박스 높이는 각도에 따라 달라짐), 전환 애니메이션은 선을 카드와 별도 취급(`width`를 늘렸다 줄이며 흩어짐과 동기화)해 "연동" 문제를 해소했고, z-index는 항상 `auto`(카드보다 항상 아래)로 고정해 "카드 위에 옴" 문제를 없앴다. 두께 4px, 파이프처럼 보이도록 수직 그라디언트(위쪽 밝게)+길이 방향 마스크 페이드를 적용. **교훈**: 같은 기능의 증상이 형태를 바꿔가며 계속 재발하면, 매번 그 자리에서 패치하지 말고 공통된 "표현 방식" 자체를 의심할 것 — 여기서는 "실제 3D 회전으로 위치 지정"이라는 선택 하나가 세 가지 다른 증상의 근원이었다.

### 그리드 다섯 번째 재수정 — "따로 논다"/"굵기 요동" 재발 원인은 빌보드 누락
4차 수정(2D 화면 좌표계로 전환) 직후에도 사용자가 "그리드가 카드랑 따로 논다", "회전하면 굵어졌다가 가늘어진다"고 재보고 — 이번엔 4차 수정 자체의 계산은 맞았지만 **적용이 미완성**이었다. 선을 담는 `div`가 3D로 회전하는 부모 씬(`#networkScene`, `transform-style:preserve-3d`)의 자식인데, 카드들과 달리 부모 회전을 상쇄하는 처리가 없어서 "2D로 계산한 회전값"이 여전히 부모의 3D 기울기 위에 얹혀 다시 뒤틀렸다. 카드가 이미 쓰고 있던 것과 정확히 같은 공식(`rotateY(-yaw) rotateX(-pitch)`, 부모 회전의 역행렬)을 선에도 추가해 완전히 평평하게 만든 뒤에야 실제로 두께가 고정됐다 — 카메라를 돌리기 전/후 실제 스크린샷을 비교해 확인(지난 라운드에 썼던 `getComputedStyle().height` 검증은 선언된 CSS 값만 읽어서 이 버그를 놓쳤었다 — 렌더링 결과 검증에는 반드시 실제 화면 캡처가 필요하다는 교훈 재확인). 두께도 "너무 굵다"는 피드백으로 4px→2.2px로 줄였다.

### 그리드 여섯 번째(최종) 재수정 — "카드 위에 옴"의 진짜 원인은 z-index가 아니라 preserve-3d
5차 수정 이후에도 "그리드가 카드 위에 오면 안 된다"는 재지적을 받았다. 원인은 z-index 설정과 무관했다: `#networkScene`가 `transform-style:preserve-3d`라서, 그 안의 카드·선은 CSS z-index가 아니라 **실제 3D 깊이(Z 위치)로 그리기 순서가 정해진다.** 카드는 궤도를 돌며 Z값이 수시로 양/음으로 바뀌는데, 선은 Z=0에 고정돼 있어서 카드가 Z=0보다 "카메라에서 먼" 쪽(음수)으로 갈 때마다 선이 그 카드보다 앞으로 그려졌다 — z-index를 아무리 조정해도 preserve-3d 안에서는 무시되는 경우였다. **최종 수정**: 선을 아예 `#networkScene`(3D 컨텍스트) 밖으로 꺼내서, `#networkShell` 안에 별도의 평면(2D) 형제 레이어 `#networkEdges`를 만들고 씬보다 DOM상 앞쪽에 배치했다. 3D 깊이 정렬에 전혀 참여하지 않는 평면 레이어이므로, 일반적인 페인트 순서(나중에 그려지는 `#networkScene`이 항상 위)만으로 카드가 항상 선 위에 오는 게 100% 보장된다. 이 구조 변경 덕에 5차에서 추가했던 빌보드 상쇄 회전도 불필요해져 제거(평면 레이어에는 애초에 상쇄할 부모 3D 기울기가 없음). scatter 애니메이션·접기 애니메이션 등 `networkScene.children`을 순회하던 모든 코드를 `networkEdges`도 함께 포함하도록 수정.

### 그룹 카드 재선택 시 하부 접기(토글) — 허브 클릭 = 뒤로 가기, 애니메이션 포함(2026-08-25, 2차 개선까지, ※애니메이션 방식은 "카드 위치 이동 금지" 규칙으로 이후 대체됨 — 아래 참고)
"그룹 카드를 선택 시 하부가 펼쳐지고, 다시 그룹 카드를 선택하면 하부가 오므라져서 감춰지게" — 그룹을 클릭해 들어가면 그 그룹이 화면 중앙의 "허브"가 되는데, 지금까지 허브는 클릭이 안 되는 순수 장식이었다. 이제 허브를 클릭하면 좌상단 뒤로 가기 버튼과 동일하게 상위 레벨로 복귀한다. **클릭 신뢰성 함정**: 허브는 화면 정중앙에 크게 떠 있지만 z-index가 낮게 고정돼 있어(태양 앞을 행성이 지나가는 연출을 위해 의도적으로) 궤도를 도는 다른 카드가 순간적으로 허브 자리를 가리면 클릭이 그 카드로 잘못 인식될 수 있었다. 클릭 좌표가 허브의 화면 영역 안에 들어오면 다른 무엇이 위에 떠 있든 무조건 허브 클릭으로 우선 처리하도록 수정 — Playwright로 궤도가 실제로 도는 상태에서 5회 연속 클릭해 5/5 성공 확인.
- **접기 애니메이션 범위 재조정 — 2차례 걸쳐 완성**:
  - *2차*(사용자 피드백: "해당 카드의 하부 카드들만 모이고, 나머지 그룹카드는 오므려들지 않게... 다 모이고 나면 그룹 카드들만 남으니까, 그것들은 다시 적당한 간격을 취해줘"): 처음 버전은 화면의 모든 카드(펼쳐졌던 하부는 물론, 배경의 형제 그룹 카드까지)를 한꺼번에 오므렸는데 어색했다. 닫힘 단계(허브+현재 링만 중심으로 모여 사라짐, 배경 형제는 완전히 그대로 둠)와 재배치 단계(스택 pop 후 배경 카드를 DOM 재사용으로 새 간격·크기에 부드럽게 전환)로 분리.
  - *3차*(사용자 재지적: "선택된 그룹 카드는 크기가 변동되지 말고, 주변의 카드들이 모여줘... 다 모였으면, 그룹 카드가 원래의 자기 자리로 찾아가는 과정을 보여줘... 전체적으로 축소되고 멀리서 그룹카드 한 개가 다시 나타나는 게 아니고"): 2차 버전은 닫힘 단계에서 허브 자체도 함께 줄어들어 사라졌다가, 재배치 단계에서 완전히 새로운 카드가 fade-in하는 방식이었다 — 이게 "그룹 카드가 사라졌다 멀리서 다시 나타남"으로 보였던 것. **수정**: 닫힘 단계에서 허브(선택된 그룹 카드 자신)는 위치·크기 모두 절대 건드리지 않고, 오직 그 하부(현재 링) 카드들만 모여들어 사라지게 함. 재배치 단계에서는 허브였던 그 카드를 "새로운 항목"이 아니라 "허브 위치/크기 그대로 얼어있던 카드"로 인식해, 그 마지막 렌더 상태를 그대로 물려받는 새 버튼을 만들고, 거기서부터 자기 자리(새 최상위 링의 정상 위치)로 이동하는 애니메이션을 재생 — 카드 자체의 연속성이 완전히 보존된다.
- **사용자가 영구 기억을 명시적으로 요청한 원칙**: "앞으로 움직이는 것, 상태 변화하는 것에 대해서 모든 변환 과정이 나타나야 해. 갑자기 퍽 나타나는 거는 안 돼." — Claude 메모리 `always-animate-transitions`에 영구 정책으로 저장함. 앞으로 이 프로젝트든 다른 프로젝트든 상태/위치가 바뀌는 UI를 만들 때 항상 적용.

### 그룹 진입(펼치기) 시에도 하부 카드가 "갑자기 나타남" — 접기의 반대 방향도 동일하게 수정(2026-08-25, ※스폰 애니메이션은 "카드 위치 이동 금지" 규칙으로 이후 대체됨 — 아래 참고)
"그룹카드를 선택시 하부카드가 갑자기 나타난다. 부모카드에서 분리되어 나오는 과정을 넣어줘." 지금까지 접기(뒤로 가기) 방향은 여러 차례 다듬었지만, 펼치기(그룹 진입) 방향(`pushNetworkLevel`)은 손대지 않아 여전히 하드 컷이었다 — DOM을 다시 그리면서 새 하부 카드들이 처음부터 최종 위치·크기·투명도로 바로 나타났다. **수정**: 새 DOM을 정상적으로 만든 뒤, 허브를 제외한 모든 카드·연결선을 허브 위치(원점)·작은 크기·투명도 0으로 순간 되돌리고, 리플로우를 강제한 다음 원래(자연) 목표 값으로 트랜지션 — 하부 카드들이 허브에서 "갈라져 나와" 각자의 궤도 자리로 퍼지는 것처럼 보인다. 허브 자체는 이 되돌림에서 제외했다 — 클릭 직전 애니메이션이 이미 그 카드를 허브 위치/크기로 옮겨놓았고, 새로 그려지는 허브 div도 정확히 같은 값으로 생성되므로 같은 프레임에서 바뀌어도 티가 안 난다(접기 방향과 달리 여기선 신구 허브 값이 애초에 동일함). **부수적으로 발견한 타이밍 문제**: 이 스폰 애니메이션이 비동기(끝나는 시점이 함수 리턴보다 한참 뒤)라서, "전환 중" 플래그를 반드시 애니메이션이 실제로 끝날 때까지 유지해야 했다 — 이전에는 애니메이션이 끝나기 전에 플래그가 풀려서, 애니메이션 총 소요 시간이 480ms→약 950ms로 늘어난 걸 놓치면 "방금 들어간 레벨에서 바로 클릭했는데 반응이 없다"는 버그로 이어질 뻔했다.

### 말단 카드를 선택한 채 화면을 돌리면 카드가 찌그러지는 버그
"말단 카드가 선택후 전체 회전하면 말단카드가 찌그러진다. 카드는 항상 정면을 봐야 한다." 원인: 카드가 "진입/포커스 중"(`.entering` 클래스) 상태일 때는 매 프레임 카메라 정면 보정 계산 자체를 완전히 건너뛰도록 되어 있었다 — 원래는 진입 애니메이션(약 480ms) 동안만 위치가 흔들리지 않게 하려는 의도였는데, 말단 카드를 포커스하면 이 클래스가 포커스를 풀 때까지 계속 남아있어서, 사실상 "포커스된 동안 내내" 정면 보정이 멈춰 있었다. 그 상태로 화면(카메라)을 돌리면, 카드 자신의 역회전 값은 포커스한 순간에 고정된 채 부모 장면만 계속 회전해서 서로 상쇄가 안 되고 뒤틀려 보였다. **수정**: `.entering` 카드도 매 프레임 건너뛰지 않고, 위치·크기는 그대로 둔 채 회전 성분만 최신 카메라 각도로 계속 갱신하도록 변경. 카메라를 120도 정도 돌린 뒤에도 포커스된 카드의 위치·크기는 완전히 그대로였고 회전만 카메라를 따라간 것을 확인했다.

### 전환이 평면적이다 — 카드 3D 텀블링 추가, 그리드 더 얇게+원근감, 선택 시 카메라가 카드로 이동(2026-08-25)
- **그리드 얇게+거리별 가늘기**: 기본 두께를 1.3px로 더 줄이고, 매 프레임 원근 투영에 쓰던 배율(`sc`, 카메라에서 먼 카드일수록 작아짐)을 선의 두께에도 그대로 곱해 카메라에서 먼 카드로 갈수록 선이 더 가늘어지게 했다(0.35~1.5배 범위로 클램프).
- **전환 시 카드가 밋밋하게 움직이는 문제**: 지금까지 도넛 카드는 흩어질 때 항상 `rotateY(0deg)`(회전 없음)로 고정돼 있었고, 네트워크 카드도 위치만 바뀌고 회전은 그대로였다 — 실제로는 3D 이동인데도 시각적으로 납작하게 느껴진 이유. **수정**: 흩어지는 동안(도착 지점은 그대로 정확한 원래 자리)에만 무작위 3축 회전(텀블링, ±150°)과 방향에 무작위 편차(±25~50%)를 추가해 카드마다 다르게, 입체적으로 날아가 보이게 했다. 최종 도착 위치·회전·크기는 전혀 안 바뀌므로 상태가 꼬일 위험은 없다.
- **카드 선택 시 카메라가 그 카드 쪽으로 움직임 — 도입 → 제거 → 최종적으로 유일한 선택 표현 방식으로 재도입**: 처음엔 클릭된 카드가 원점으로 날아가는 것과 동시에 카메라도 그쪽을 보도록 회전시켰다가, "다른 카드를 선택하면 카메라 각도가 리셋된다"는 피드백으로 카메라 이동 기능만 제거했었다. 그런데 이후 "말단 카드끼리만 자리를 바꾸고 카메라는 안 움직인다"는 문제가 재현되면서, 실은 카메라가 아니라 **카드가 자리를 옮기는 것 자체**가 문제였음이 드러났다 — 자세한 경위와 최종 규칙은 "카드 위치 이동 금지 + 카메라 이동으로 선택 표현" 절 참고.

### 배경 그룹 카드 클릭 가능 — 선택 시 현재 그룹 닫고 선택된 그룹으로 이동(2026-08-25)
"하부카드가 펼쳐진 경우, 상부 그룹카드를 선택시 현재의 그룹은 닫고, 선택된 그룹이 펼쳐지게 해줘." 지금까지 배경(상위 링)에 보이던 카드들은 장식용으로 클릭이 안 됐다. 이제 모든 카드가 클릭 가능해졌고, 배경 카드를 클릭하면 `networkStack`을 그 카드가 속한 레벨까지 잘라낸 뒤(`networkStack.length = 그 레벨+1`) 그 자리에서 곧바로 클릭한 카드로 새로 진입한다 — 즉 "현재 펼쳐진 걸 닫고 선택한 걸 편다"가 한 동작으로 자연스럽게 처리된다. 일반 하부 카드 클릭과 동일한 애니메이션(형제 흐려짐, 클릭한 카드가 허브 자리로 날아감, 카메라도 함께 이동)을 그대로 재사용했다.

### 그리드 굵기 안정화 — "처음엔 굵다가 점점 가늘어짐"의 원인은 드리프트가 아니라 편차 폭
"그리드가 처음에는 굵었다가 카드 전환을 반복하면 점차로 가늘어진다... 가늘게 보이는 상태의 굵기가 딱 좋으니, 그 굵기를 처음부터 유지해줘." 원근 배율에 따라 매 프레임 새로 계산되는 값이라 실제로 누적되며 드리프트하는 건 아니었지만, 허용 범위(0.35~1.5배)가 넓어서 카드마다 깊이 편차가 크게 드러나 보였다 — 처음 빌드 직후 카메라에 가까운 카드가 우연히 많으면 "굵게 시작"하는 것처럼 느껴지고, 궤도가 퍼지면서 "점점 가늘어지는" 것처럼 보인 것. 범위를 0.8~1.1배로 크게 좁히고 기본 두께도 1.3px→1.5px로 살짝 올려(최종 범위 1.2~1.65px) 안정적이면서도 항상 잘 보이게 했다.

### 말단 카드 선택 후 카메라 이동 직후 드래그하면 흐름이 끊기는 버그
"하부 그룹이 펼쳐진 상태에서 말단카드를 선택시 카메라 이동후 재개될 때 흐름이 끊긴다." 원인: 카드 선택 시 카메라를 돌리는 애니메이션(CSS transition)이 실제로 정리(제거)되는 시점이, "이제 다른 조작을 받아도 된다"는 내부 플래그가 풀리는 시점보다 60ms 늦었다. 그 틈(480~540ms) 사이에 사용자가 바로 화면을 드래그하면, 드래그가 매 프레임 그리는 회전값이 아직 안 지워진 예전 트랜지션에 걸려 부드럽게 따라가지 못하고 뭉개져 보였다. **수정**: 드래그가 시작되는 바로 그 순간 무조건 트랜지션을 강제로 제거하도록 해서, 어떤 애니메이션의 잔여물이든 다음 드래그를 방해하지 못하게 했다.

### 버튼 위치 조정 및 "전환 중 카드가 정면을 잃는" 근본 버그 수정(2026-08-25)
- **버튼 위치**: 좌상단 "부모로 이동" 버튼(`left:44%`)과 우상단 모드 전환 버튼(`right:3%`)이 카드 콘텐츠 영역 가장자리에 딱 붙어 있어 "너무 떨어져 있다"는 지적을 받았다. 각각 콘텐츠 영역 중심 쪽으로 20%가량(`left:49%`, `right:8%`) 이동해 카드와 더 가까워 보이게 했다.
- **전환 중 카드가 정면을 잃는 버그**: "카드간 클릭시 주변카드 전체가 그대로 회전하고 갑자기 전부 다시 나타나 전면을 보는데, 전환도중 전면을 바라보게 해줘." 원인은 "전환 중"이라는 플래그 하나가 서로 다른 두 가지(위치를 고정할지, 카메라 정면 보정을 계속할지)를 한꺼번에 막고 있었던 것 — 카드 선택 시 카메라가 함께 회전하는 기능을 추가하면서, 카메라는 실제로 도는데 다른 카드들의 정면 보정 계산은 통째로 멈춰있어서 카메라를 따라 함께 기울어져 보이다가 전환이 끝나는 순간 갑자기 정면으로 스냅됐다. **수정**: "위치 고정"과 "회전 보정 갱신"을 분리해서, 위치는 여전히 전환 중엔 고정하되 회전 보정만은 매 프레임 계속 갱신하도록 했다. 이 변경으로 새로 생겨나는 하부 카드들의 "허브에서 태어나는" 스폰 애니메이션이 매 프레임 재계산에 깨질 뻔했는데, 스폰 중인 카드 전체에도 기존 "회전만 갱신, 위치는 그대로" 예외 처리(원래 포커스된 카드 한 장에만 쓰던 것)를 넓혀 적용해 해결했다.

### 그리드 재차 축소 + 말단 카드 포커스 시 주변 카드 동시 후퇴(2026-08-25, ※"후퇴(recede)" 효과는 "카드 위치 이동 금지" 규칙으로 이후 제거됨 — 아래 참고)
- **그리드 재차 축소**: "제일 처음에 나타나는 그리드가 굵다", "전환시 나타나는 그리드도 굵다" — 지난 라운드에 안정화한 범위(1.2~1.65px)도 여전히 굵게 느껴진다는 재요청으로, 정확한 원인을 더 파고들기보다 요청대로 두 차례 더 줄였다(기본 1.5px→1px, 허용폭 0.8~1.1배→0.85~1.05배, 최종 범위 0.85~1.05px).
- **말단 카드 포커스 시 "다시 나타나는" 현상**: "선택되어 중심으로 이동할때 주변카드도 그에 맞게 뒤로 이동되게 해줘. 지금은 선택된 카드가 중심을 잡고 주변에서 다시 나타난다." 원인: 포커스 상태를 나타내는 값이 카드가 중심으로 날아가는 애니메이션이 **다 끝난 뒤에야** 설정되고 있었다 — 그래서 날아가는 동안 주변 카드는 흐려지기만 할 뿐 제자리에 그대로 있다가, 애니메이션이 끝나는 순간 갑자기(트랜지션 없이 한 프레임 만에) 작아지고 뒤로 밀려나 "다시 나타나는" 것처럼 보였다. 포커스 상태를 카드가 날아가기 **시작하는 순간**으로 앞당기고, 주변 카드에도 트랜지션을 걸어서 선택된 카드가 중심으로 이동하는 것과 정확히 같은 시간 동안 함께 뒤로 물러나도록 고쳤다. 포커스를 해제할 때(원래대로 돌아올 때)도 같은 방식으로 애니메이션이 걸리도록 대칭으로 수정했다.

### 카드 블러 제거 + "전환 반복 시 그리드가 거의 없어짐"의 진짜 원인(2026-08-25)
- **카드 화면이 흐림**: 배경(상위 링) 카드에 "receded" 느낌을 주려고 채도 감소와 함께 블러도 걸었었는데, 이제 배경 카드도 클릭 가능한 실제 콘텐츠가 된 마당에 블러가 가독성을 해쳤다. 블러를 제거하고 채도 감소만 남겼다.
- **그리드가 반복 전환 시 사라짐 — 실측으로 원인 확정**: 추측 대신 Playwright로 "진입→뒤로가기"를 4회 반복하며 매번 연결선 투명도를 직접 측정했다. 결과: 뒤로가기(`backNetworkLevel`) 직후에만, **매번 예외 없이** 최소 투명도가 0으로 나왔다(진입 시엔 정상). 원인: 방금까지 허브였던 카드가 다시 보통 카드로 복귀할 때 연결선을 새로 만드는데, 이 새 연결선은 투명도 0으로 "씨앗" 상태로 시작하도록 되어 있었고, 이후 원래 밝기로 되돌리는 코드가 카드(이미지)에는 있었지만 연결선에는 빠져 있었다 — 그래서 뒤로 갈 때마다 최소 하나씩 선이 영구히 투명한 채로 남았다. 재사용되는 다른 배경 카드들의 선도 새 링에 맞는 밝기로 안 갱신되고 이전 값에 머물러 있던 부수적 문제도 같이 발견해 함께 고쳤다. 수정 후 4회 반복 측정에서 매번 정상 밝기(0.85)로 유지됨을 확인. (아래 "카드 위치 이동 금지" 규칙 확정 이후 이 버그의 원인이 된 메커니즘 자체가 통째로 사라졌다.)

### 카드 위치 이동 금지 + 카메라 이동으로 선택 표현 — 최종 아키텍처 확정(2026-08-25, 이 날의 마지막 재설계, 이전 애니메이션 설계 다수를 대체)
사용자 직접 지시, 영구 규칙: **"카드간의 위치 이동은 절대 없다. 처음이나 끝이나. 그룹 카드나 말단카드나. 모든 카드는 고유의 궤적을 회전하는 것이고, 선택된 카드로 카메라가 이동하는 것이다."**

경위: 처음엔 클릭한 카드가 중앙(허브 자리)으로 날아가 확대되는 방식뿐이었다 → 여기에 카메라도 함께 도는 기능을 추가했다("전환이 평면적이다" 절 참고) → "다른 카드 선택시 카메라 각도가 리셋된다"는 피드백으로 카메라 이동 기능만 제거하고 카드가 날아가는 방식은 그대로 두었다 → 그런데 "말단 카드가 이미 포커스된 상태에서 다른 말단 카드를 선택하면, 카메라는 안 움직이고 카드끼리만 자리를 맞바꾼다"는 정확히 같은 부류의 문제가 재현됐고, 이때 사용자가 위 영구 규칙을 명시적으로 지시했다 — 문제는 카메라 기능이 아니라 애초에 **카드가 위치를 바꾸는 것 자체**였다.

**최종 구현**: 모든 카드(그룹·말단 불문)는 선택 여부와 무관하게 항상 자기 궤도만 계속 돈다 — 위치·크기 절대 불변, 선택돼도 화면 중앙으로 이동하거나 커지지 않는다. 대신 **카메라(시야각)** 만 선택된 카드가 있는 방향을 보도록 매끄럽게 회전한다. 카메라 이동은 CSS 트랜지션이 아니라 매 프레임 JS로 각도를 보간하는 방식으로 구현했는데, CSS 트랜지션을 쓰면 카메라(컨테이너)는 서서히 도는데 각 카드의 "카메라를 향해 정면을 유지하는" 반대회전 계산은 목표각을 즉시 참조해버려서 카드가 잠깐 일그러져 보이는 문제가 있었기 때문이다.

이 규칙에 따라 제거된 것들(전부 "카드가 위치/크기를 바꾸는" 애니메이션이었음): 카드가 허브 위치로 날아가 확대되는 효과, 선택 시 나머지 카드가 뒤로 빠지는 효과(recede), 그룹 진입 시 하부 카드가 허브에서 튀어나오듯 펼쳐지는 스폰 애니메이션, 허브 접기 시 카드가 자기 자리로 이동하며 접히는 애니메이션(및 이를 위해 있던 복잡한 "요소 재사용" 로직 전체). 전부 **불투명도 페이드**로 대체했다 — 선택 시 나머지 카드는 흐려지기만 하고, 레벨을 오갈 때는 카드가 사라졌다 나타나는 대신 페이드 아웃/인만 한다. (※같은 날 뒤쪽 라운드에서, 접기 방향에 한해 "하부 카드가 그룹 카드로 모여드는" 위치 애니메이션만 사용자 요청으로 다시 추가됨 — 아래 "굵은 테두리 재발" 다음 라운드 참고. 펼치기/선택 방향은 이 규칙 그대로 유지.)

부수 효과: 위 "그리드가 사라짐" 버그의 원인이었던 요소별 상태 이어받기 로직이 통째로 사라져, 같은 버그가 구조적으로 재발할 수 없게 됐다. Playwright로 재검증: 말단 카드를 연속으로 재선택할 때 카메라 각도가 매번 실제로 바뀌고, 두 카드의 좌표는 궤도상 정상적인 미세한 변화만 있을 뿐 순간이동하거나 서로 자리를 바꾸지 않음을 확인. 반복적인 진입/뒤로가기 3회에서도 그리드 투명도가 항상 정상 범위(0.53~0.85)로 유지됨을 확인.

### 선택된 카드를 카메라가 계속 추적(지구중심 시점) + 카드 화면 흐림 진짜 원인 해결(2026-08-25, 같은 날 마지막 라운드)
- **카메라 지속 추적** (2026-08-25, ※이 방식은 바로 다음 라운드에서 "렌더링 원점 이동" 방식으로 대체됨 — 아래 "선택 카메라 방식 재수정" 절 참고): "선택된 카드가 중심으로 보이는 효과를 내줘. 카메라가 계속 따라다니는 거다. 선택된 카드는 중앙에 정지될 것이고, 주변 카드가 움직일 거다. 지구에서 보면 달이나 태양이 움직이는 것처럼." 바로 위 절의 카메라 이동은 클릭 시점 위치를 한 번만 조준하는 방식이라, 조준이 끝난 뒤에도 카드는 계속 궤도를 돌기 때문에 서서히 화면 중심에서 벗어나는 점이 남아있었다. **수정**: 매 프레임 그 카드의 "지금 이 순간" 궤도 좌표를 다시 조준해 카메라 각도를 그 방향으로 조금씩(부드럽게) 맞춰가는 지속 추적 방식으로 교체했다. 목표 각도 자체가 매 프레임 거의 안 바뀌는 수준으로만 갱신되기 때문에, 처음 선택할 때는 부드럽게 다가가는 느낌을 주면서도 이후엔 거의 완벽하게 화면 중앙에 고정된 것처럼 보인다 — 정확히 사용자가 말한 "선택된 것은 정지, 나머지가 움직인다"는 지구중심적 시점. 드래그하면 일시적으로 추적을 멈추고 자유롭게 둘러볼 수 있고, 손을 떼면 다시 부드럽게 원래 카드를 추적한다. Playwright 검증: 포커스된 카드의 화면 좌표가 약 1.2초(6프레임 샘플) 동안 1px 이내로 고정된 반면, 옆의 다른 카드는 같은 시간에 화면에서 약 180px 이동하고 카메라 각도는 계속(38도가량) 바뀜을 확인. **이 방식의 부작용**: "각도를 매 프레임 강제로 다시 맞춘다"는 게 핵심이었으므로, 드래그로 각도를 바꿔도 손을 떼는 즉시 다시 원래 조준 각도로 서서히 되돌아가는 문제가 있었다(다음 라운드에서 재지적됨).

### 선택 카메라 방식 재수정 — 각도 강제 조준 대신 "렌더링 원점을 선택된 카드로 이동" + 선택 카드 확대(2026-08-25, 같은 날 마지막 라운드)
"선택된 카드가 중앙에서 크게 보이게 해주고, 궤적을 보는 각도를 바꿀때 바뀐 궤적을 유지하게 해줘. 자꾸 원래로 돌아간다." 위 절의 "카메라 지속 추적" 방식은 매 프레임 카메라 각도(요/피치)를 선택된 카드 쪽으로 강제로 다시 맞추는 방식이었는데, "look-at 각도"는 어떤 위치를 정면으로 보기 위한 각도가 수학적으로 딱 하나뿐이라서, 사용자가 드래그로 다른 각도를 만들어도 손을 떼는 순간 그 유일한 정답 각도로 도로 끌려갔다 — "자꾸 원래로 돌아간다"는 정확히 이 현상이었다.

**수정**: 카메라 각도를 강제로 조정하는 로직을 완전히 없애고, 대신 **매 프레임 렌더링에 쓰는 좌표계의 기준점(원점)을 선택된 카드의 실시간 위치로 옮기는** 방식으로 바꿨다. 원래 허브(중심 태양 카드)는 항상 로컬 좌표 원점 `(0,0,0)`에 있고, 이 원점은 카메라를 어떤 각도로 돌리든 항상 화면 정중앙에 투영된다는 불변의 성질을 이 시스템이 처음부터 갖고 있었다 — 이 성질을 그대로 재사용해서, 매 프레임 "선택된 카드의 현재 위치"를 빼주는 방식으로 모든 카드(허브 포함)의 좌표를 다시 계산하면, 선택된 카드는 계산상 항상 정확히 원점이 되어 **카메라 각도와 무관하게 항상 화면 중앙에 나타난다.** 이제 카메라 각도는 순전히 드래그(및 그 관성)에 의해서만 바뀌므로, 사용자가 만든 각도가 그대로 유지된다.

**"크게 보이게" 요청도 함께 반영**: 선택된 카드가 이제 원점(허브 자리)을 차지하게 된 김에, 허브와 같은 확대 배율(약 1.85배)로 부드럽게(순간적으로 팍 커지지 않고) 커지도록 만들었다. (참고: 이때 "선택 해제 시에도 부드럽게 줄어든다"고 의도했으나 실제로는 순간적으로 팍 줄어드는 버그가 있었음 — 바로 다음 라운드에서 발견·수정됨)

**부수적으로 필요했던 수정**: 연결선(그리드)이 기존에는 "허브는 항상 화면 중앙"이라는 가정하에 원점에서부터의 거리·각도만 계산해서 그렸는데, 이제 허브도 다른 카드처럼 화면 중앙을 벗어날 수 있게 되어, 연결선을 "허브의 실제 화면 위치 → 카드의 실제 화면 위치"를 정확히 계산해서 잇는 방식으로 바꿨다. 카드들이 화면에 그려지는 순서(깊이 정렬)는 이 좌표 이동에 영향받지 않는다(모든 카드에 같은 양만큼 이동을 적용했으므로 카드 간 상대적 거리는 그대로 유지되기 때문).

**검증**: Playwright로 포커스된 카드의 화면 좌표가 화면 중앙과 서브픽셀 단위로 일치하고 실제 렌더 크기가 약 1.85배(96×128px → 약 178×237px)로 커짐을 확인. 드래그로 카메라 각도를 크게 바꾼 뒤 1.5초 대기해도 각도가 드래그 이전 값으로 전혀 되돌아가지 않고(관성에 의한 자연스러운 감속만 있을 뿐 방향이 역전되지 않음) 유지됨을 확인. 그룹 진입, 배경 카드 클릭, 말단 카드 포커스/해제, 3회 반복 뒤로가기를 전부 재검증해 콘솔 에러 없음을 확인.

### 포커스 크기·전환 애니메이션 미세 조정 + 동급 카드 안 흐리기 + 그룹/포커스 테두리 구분(2026-08-25, 같은 날 마지막 라운드)
"포커스를 잃은 카드는 다시 원 크기로 돌아가게 해줘. 포커스된 것이 말단 카드일때 동급의 카드들로 잘보이게 해줘. 흐리게 하지 말고. 그룹카드들은 테두리를 넣어 다른 것과 구분해주고, 현재 포커스된 카드는 더 굵은 테두리를 넣어줘. 테두리가 굵은 만큼 약간 흐리게 하자. 물론 현재처럼 포커스를 잃으면 테두리는 없어지게 해줘. 카드의 포커스가 전환될때 전환과정을 보여줘." 바로 위 라운드에서 두 가지가 실제로는 의도한 대로 동작하지 않고 있었다.

- **① 포커스 해제 시 순간적으로 줄어드는 버그**: 커지는 배율 값을 "선택된 카드 한 장"에만 적용하는 공용 변수 하나로 관리했는데, 포커스가 풀리는 순간 그 변수를 적용할 대상 자체가 사라져서 스르륵 줄어드는 과정 없이 즉시 원래 크기로 튀었다. **수정**: 배율 값을 카드마다 각자 갖고 있도록(즉 카드 각자가 "지금 내가 몇 배로 보여야 하는지"를 계속 스스로 추적) 바꿔서, 포커스를 잃은 카드도 자기 힘으로 원래 크기까지 부드럽게 줄어들도록 했다.
- **② 포커스가 다른 카드로 바뀔 때 화면이 순간 이동하던 문제**: "화면 중심을 선택된 카드로 옮기는" 계산이 매 프레임 선택된 카드의 "지금 위치"를 그대로 가져다 썼는데, 선택이 A카드에서 B카드로 바뀌는 순간 그 위치가 한 프레임 만에 뚝 바뀌어서 화면 전체가 순간 이동하는 것처럼 보였다. **수정**: 이 기준점도 매 프레임 목표 위치로 부드럽게 다가가도록(스냅이 아니라 이동) 바꿔서, 카드 간 포커스 전환도 화면이 자연스럽게 이어지며 넘어가도록 했다.
- **③ 말단 카드 포커스 시 동급 카드를 흐리게 하지 않음**: 지금까지는 카드를 포커스하면 나머지 전부(같은 단계 카드 포함)를 흐리게 만들었는데, 말단 카드를 포커스했을 때만은 같은 단계(동급)의 카드는 흐리게 하지 않고 그대로 선명하게 보이도록 바꿨다(상위 그룹의 배경 카드는 계속 흐리게 유지 — "동급"이 아니므로). 그룹 카드를 눌러 하위로 진입할 때의 흐림 처리는 기존 그대로 유지했다(사용자가 "말단 카드일 때"로 콕 집어 요청했기 때문).
- **④ 그룹/포커스 카드 테두리 구분**: 동급 카드를 더 이상 흐리게 하지 않게 되면서, "지금 무엇이 포커스됐는지"를 다른 방식으로 보여줄 필요가 생겼다. 하위 그룹으로 이어지는(즉 눌러도 최종 작품이 아니라 또 다른 목록으로 들어가는) 카드에는 항상 은은한 보라색 테두리를 넣어 일반 카드와 구분되게 했고, 그중 현재 포커스된 카드는 테두리를 더 두껍게 하고 부드럽게 번지는 은은한 빛(그림자 효과)을 추가했다 — 사용자가 말한 "테두리가 굵은 만큼 약간 흐리게"는 카드 사진 자체를 흐리게 하는 게 아니라 테두리 주변에 부드러운 빛 번짐 효과를 주는 것으로 구현했다(사진이 흐려 보이는 문제는 이미 이전 라운드에서 별도로 고쳤으므로, 사진 자체는 계속 선명하게 유지). 포커스를 잃으면 이 두꺼운 테두리와 빛 효과도 부드럽게 사라진다.

**검증**: Playwright로 그룹 단계 카드에 테두리가 있고 말단(최종 목록) 단계 카드에는 없음을 확인, 말단 카드 포커스 중 옆 카드 불투명도가 그대로 1(안 흐려짐)임을 확인, 포커스된 카드가 굵은 테두리 클래스를 갖고 실제 확대 배율이 약 1.85배임을 확인, A카드에서 B카드로 포커스를 옮길 때 화면 기준점이 여러 프레임에 걸쳐 서서히 이동함(한 프레임 순간이동이 아님)을 확인, 포커스 해제 후 확대 배율이 약 1.0으로 부드럽게 돌아오고 테두리 클래스도 사라짐을 확인. 그룹 진입·배경 카드 클릭·반복 뒤로가기까지 전부 콘솔 에러 없이 통과.

### 그룹 카드(허브)가 멤버 선택 후에도 계속 크게 남아있던 버그 수정(2026-08-25, 같은 날 마지막 라운드)
"선택된 그룹 카드 상태에서 멤버를 선택하면, 멤버는 크게, 크게 커져서 가운데 중앙 위치하는데, 그룹 카드는 원래대로 작게 돌아가지 않는다." 지금까지 그룹의 중심 카드(허브 — 현재 들어와 있는 그룹을 나타내는 태양 역할의 카드)는 항상 고정된 확대 배율로만 그려지고 있었다. 이는 원래 의도된 동작이었지만(허브는 "지금 여기에 있다"는 표시로 항상 커야 함), 이번 세션에서 확정한 "커질 때는 선택받은 카드 뿐이다"라는 규칙과 충돌했다 — 그 그룹 안의 멤버 카드를 선택하면 멤버가 커지는데, 허브도 여전히 계속 크게 남아 있어서 화면에 큰 카드가 두 개 동시에 있는 것처럼 보였다.

**수정**: 허브도 다른 카드들과 마찬가지로 "지금 내가 몇 배로 보여야 하는지"를 스스로 부드럽게 추적하도록 만들었다 — 멤버가 선택되면 허브는 원래 크기로 작아지고(선택이 다른 곳으로 옮겨갔으므로), 아무것도 선택되지 않은 상태(그냥 둘러보는 중)로 돌아가면 허브가 다시 원래의 확대된 크기로 돌아온다. 이제 항상 "선택된 카드 단 하나만" 화면에서 크게 보인다.

**검증**: Playwright로 하위 단계까지 들어가 허브가 있는 상태를 만든 뒤, 멤버 카드를 선택하기 전(허브 배율 약 1.85) → 선택 후(허브 배율 약 1.00, 멤버 배율 약 1.85로 성장) → 다시 선택 해제 후(허브 배율 약 1.85로 복귀)까지 전부 확인. 전환 중간 스크린샷으로 멤버가 커지는 것과 허브가 작아지는 것이 동시에 부드럽게 진행됨을 시각적으로도 확인. 최상위 레벨(허브 없음)로 되돌아가는 반복 뒤로가기까지 콘솔 에러 없이 통과.

### 굵은 테두리 표시 기준을 "선택/중앙"에서 "마우스 오버"로 전면 교체(2026-08-25, 같은 날 마지막 라운드)
"포커스를 받을 때에만 두꺼운 테두리를 주게끔 했는데, 항상 두꺼운 테두리가 있다. 두꺼운 테두리는 중앙가운데 카드에 주지말고, 마우스 오버시에 포커를 받는 카드에 주자." 추측하지 않고 Playwright로 직접 확인한 결과: 방금 만든 "선택 시 굵은 테두리" 기능 자체는 코드상 정확히 의도대로 동작하고 있었다(아무것도 선택 안 됐을 때 굵은 테두리를 가진 카드는 실제로 하나도 없었음). "항상 굵은 테두리가 있다"고 느껴진 진짜 원인은 따로 있었다 — 그룹의 중심 카드(허브)에는 이번 세션 이전부터(8월 23일) 이미 은은한 보라색 테두리와 빛 번짐 효과가 항상 걸려 있었는데, 허브는 대부분의 상황에서 화면 중앙에 있다 보니 "중앙 카드는 늘 굵게 테두리가 있다"는 인상을 줬던 것.

사용자는 이 기회에 아예 방식을 바꾸기로 했다: 선택되어 중앙에 있는 카드에는 테두리 강조를 아예 주지 말고(크고 중앙에 있는 것 자체로 충분한 표시), 대신 마우스를 올린(hover) 카드에만 굵고 빛나는 테두리가 나타나게 하자는 것.

**수정**: 방금 만들었던 "선택 시 굵은 테두리" JS 로직을 완전히 제거하고, 그 스타일(굵은 테두리 + 은은한 빛 번짐)을 CSS의 순수 마우스 오버 효과로 옮겼다 — 어떤 카드든 마우스를 올리면 자동으로 굵은 테두리가 나타나고 떼면 부드럽게 사라진다(그룹/말단, 선택 여부와 무관하게 전부 동일하게 적용). 또한 허브의 원래 있던 테두리 빛 번짐 효과도 제거해서, 중앙에 있다는 이유만으로 굵은 테두리처럼 보이는 일이 없도록 정리했다(허브 고유의 은은한 보라색 테두리 색상은 유지, 굵기는 다른 카드와 동일).

**검증**: 아무것도 선택 안 된 상태에서 굵은 테두리를 가진 카드가 없음을 확인, 허브의 그림자 효과가 일반 그림자만 남고 테두리 느낌의 링이 사라졌음을 확인, 선택되어 중앙에 있는 카드도 테두리 굵기가 기본값(1px)임을 확인, 실제 마우스 커서를 다른(선택되지 않은) 카드 위로 이동시켰을 때 그 카드만 굵은 테두리(4px)로 바뀜을 확인. 스크린샷으로 "중앙의 큰 카드는 얇은 테두리, 옆의 마우스 올린 작은 카드는 굵고 빛나는 테두리"인 것을 시각적으로도 확인.

### 같은 문제 재발 — 이번엔 "클릭 자체가 곧 마우스 오버"였던 게 진짜 원인(2026-08-25, 같은 날 마지막 라운드)
바로 위 수정을 배포한 뒤, 사용자가 정확히 같은 문장으로 다시 같은 문제를 보고했다. 추측하지 않고 다시 Playwright로 확인한 결과, 이번엔 원인이 완전히 달랐다: 카드를 클릭하면 마우스 커서는 클릭한 그 자리에 그대로 머무르는데, 방금 선택된 카드는 화면 중앙으로 커지면서 이동해오기 때문에, 전환이 끝났을 때 커서가 우연히 그 커진 카드 위에 그대로 놓여 있게 되는 경우가 잦았다 — 이건 "의도치 않게 남아있는 것"이지만 브라우저 입장에서는 진짜로 그 카드를 hover하고 있는 상태라서, 순수 CSS 마우스 오버 효과만으로는 "일부러 올린 것"과 "클릭하고 나서 우연히 남은 것"을 구분할 수 없었다.

**같은 증상, 다른 원인이었다는 점이 핵심**: 첫 번째 라운드의 원인은 허브의 오래된 고정 테두리 효과였고, 이번 라운드의 원인은 클릭이 곧 호버로 이어지는 상호작용 특성이었다 — 겉보기엔 똑같이 "항상 굵은 테두리가 있다"로 보였지만 완전히 다른 버그였다.

**수정**: 선택되어 중앙에 있는 카드는 실제 마우스가 그 위에 있는지 여부와 무관하게 항상 굵은 테두리 효과에서 제외되도록 예외 규칙을 추가했다. 이제 마우스가 우연히 선택된 카드 위에 머물러 있어도 굵은 테두리가 나타나지 않고, 오직 선택되지 않은 다른 카드에 실제로 마우스를 올렸을 때만 나타난다.

**검증**: 마우스를 화면 먼 곳에 둔 상태에서 모든 카드(선택된 카드 포함) 테두리가 기본값임을 확인, 마우스를 선택된 카드 바로 위로 직접 이동시켜도 여전히 기본 테두리로 유지됨을 확인(브라우저 hover 상태 자체와 실제 컴퓨티드 스타일을 모두 대조), 실제 "클릭 후 마우스를 움직이지 않고 그대로 두는" 시나리오를 끝까지 재현해도 방금 선택된 카드에는 절대 굵은 테두리가 나타나지 않음을 확인. (검증 과정에서 테스트 스크립트 자체의 오류도 하나 발견해 바로잡았다 — 카드 위치를 미리 읽어둔 좌표로 마우스를 이동시켰는데, 그 사이 카드가 계속 궤도를 돌고 있어서 대기 시간이 지나면 커서가 다른 카드 위에 가 있었던 것으로, 실제 버그가 아니라 측정 방법의 오차였음을 `document.elementFromPoint()`로 교차 확인해 가려냈다.)

### 그룹 카드 테두리 제거 + 첫 진입 시 카드 회전 부자연스러움 수정 + 접기 애니메이션 복원(2026-08-25, 같은 날 마지막 라운드)
"그룹 카드에 가는 테두리를 주기로 했는데, 그거는 빼죠. 처음 가상공간2로 전환할 때, 모든 카드가 기울어진 상태로 움직이다 갑자기 전면을 향함. 부드럽게 전면을 향하게 해줘. 하부가 펼쳐진 그룹카드를 선택시 하부카드들이 그룹카드로 모여 없어지고 난뒤, 그룹카드가 제위치를 찾아야하는데, 하부카드들이 모이는 과정이 없어졌다. 기존에 있었는데 확인해줘." 관련 없는 세 가지 요청을 한 번에 처리했다.

**① 그룹 카드 가는 테두리 제거**: 요청대로 완전히 뺐다. 그룹 카드를 구분하는 용도로 쓰던 CSS 클래스와 관련 로직을 전부 삭제했다.

**② 가상공간2 첫 진입 시 카드가 기울어진 채 움직이다 갑자기 정면을 향하던 문제 — 1차 시도(불완전)**: 카드가 흩어져 있다가 제자리로 모이는 애니메이션에서, 날아오는 도중엔 무작위 기울임 회전이 걸려 있는데 도착 지점 값에는 그 기울임 회전이 아예 없어서 브라우저가 매끄러운 개별 보간 대신 행렬 보간으로 전환되며 부자연스러워 보인다고 진단하고, 도착 지점에도 "기울임 없음(0도)"을 명시적으로 넣어 맞췄다. **→ 이 수정은 그 자체로는 맞았지만 문제를 해결하지 못했다 — 사용자가 "여전히 있다"고 재보고, 진짜 원인을 다시 찾음(아래 새 라운드 참고).**

**③ 그룹 카드 접기(뒤로가기) 시 "하부 카드가 모여드는" 과정 복원**: 이 문서 앞부분에서 설명한 "카드 위치 이동 금지" 영구 규칙에 따라 한때 완전히 제거됐던 기능인데, 사용자가 명확하게 "기존에 있었다"며 복원을 요청해 다시 넣었다. 단, 이번엔 선택(진입) 방향이 아니라 **접기(닫기) 방향에 한정된 예외**로 구현했다 — 사라질 하부 카드들이 자신을 흡수하는 그룹 카드(허브)의 자리로 모여들면서 작아지고 사라지는 애니메이션이며, 허브 자신과 상위(배경) 카드는 여전히 그냥 페이드만 한다. 선택 시 카메라만 움직이고 카드는 절대 움직이지 않는다는 원래 규칙은 그대로 유지된다.

**검증**: 그룹 카드에 테두리 클래스가 더 이상 없음을 확인. 그룹 진입 후 뒤로가기 시 하부 카드가 실제로 중심(원점)으로 이동하며 축소되는 것을 애니메이션 도중 좌표 값으로 직접 확인(예: x좌표 160→0, 크기 1→0.12). 진입→접기를 4회 반복해도 그리드·카드 밝기가 항상 정상 범위로 유지됨을 확인. 전 과정 콘솔 에러 없음.

### 첫 진입 회전 문제 진짜 원인 발견 + 그룹 진입도 매끄럽게 이어지도록 전면 재설계(2026-08-25, 같은 날 마지막 라운드)
"첫 진입 시 카드가 기울어진 채 움직이다 갑자기 정면을 향하던 문제가 여전히 있다. 확인해줘. 그룹카드를 선택시 하부가 펼쳐지는 과정이 없어졌다. 복원해줘. 주변의 그룹카드를 선택하면 카드가 중앙으로 오고, 그 상태에서 하부가 펼쳐지게 해줘... 그런데, 그룹카드가 중앙에 오고, 그다음 바깥에서 펼쳐진 그룹들과 함께 전체가 다시 들어온다. 매끄럽지 않다. 수정해 줘. 한마디로 어떻게 되든 끊긴다는 느낌없이 매끄럽게 넘어가야 돼. 그게 대전제야."

**① 회전 문제의 진짜 원인**: 화면 전체(카드들이 들어있는 3D 공간 컨테이너)의 회전값이 지금까지 딱 두 곳(마우스 드래그, 그리고 1.2초 동안 아무 조작이 없을 때 자동으로 살짝 도는 기능)에서만 설정되고 있었다 — 즉 페이지에 처음 들어와서 드래그를 한 번도 안 하고 1.2초도 안 지났다면, 이 컨테이너는 "전혀 안 돌아간 상태"였다. 반면 각 카드는 "컨테이너가 지금 이 정도는 돌아가 있을 것"이라고 가정하고 자기 자신을 반대로 돌려서 항상 카메라를 보게 만드는 계산을 하는데, 실제로는 컨테이너가 하나도 안 돌아가 있었으니 이 계산이 전부 어긋나 카드들이 눈에 띄게 비뚤어져 보였던 것이다. 그러다 1.2초가 지나 자동 회전 기능이 처음으로 컨테이너 회전값을 실제로 설정하는 순간, 모든 카드가 갑자기 맞아떨어지며 "정면을 향하는" 것처럼 보인 것 — 정확히 사용자가 본 증상(움직이다가 잠시 뒤 갑자기 정면을 향함)과 타이밍까지 일치했다. 이전 라운드의 수정(회전 성분 개수 맞추기)은 그 자체로는 옳았지만 진짜 원인이 아니었다.

**수정**: 카드들의 회전을 계산하는 함수 자체가 컨테이너의 회전값도 매번 함께 맞춰 쓰도록 바꿨다. 이제 이 둘이 항상 같은 곳에서, 항상 함께 갱신되므로 다시는 어긋날 수 없다.

**② 그룹 카드 선택 시 "하부가 펼쳐지는" 과정 복원 + 전체를 하나의 매끄러운 동작으로 재설계**: 지난 재설계에서 하부 카드들이 그냥 불투명도만 바뀌며 나타나도록 단순화됐던 부분을, "하부 카드들이 허브(중심 카드)로부터 뻗어나가듯 펼쳐지는" 원래 동작으로 되살렸다 — 지난 라운드에 복원한 "접힐 때 모여드는" 동작과 정확히 대칭되는, 펼칠 때 버전이다.

더 중요한 건 **끊김 없이 이어지는 문제**였다. 기존에는 (1) 클릭한 그룹 카드가 중앙으로 다 커질 때까지 기다렸다가 → (2) 그 다음에서야 화면 전체를 통째로 다시 그리며 하부 카드들이 나타나는, 완전히 분리된 두 단계였다 — 이게 정확히 "카드가 중앙에 오고, 그다음... 전체가 다시 들어온다"는 끊기는 느낌의 원인이었다. **수정**: 클릭한 카드가 다 커지기를 기다리지 않고, 훨씬 이른 시점(원래 대기시간의 약 3분의 1)에 화면 재구성을 시작하도록 바꿔서, "카드가 커지는 움직임"과 "하부가 펼쳐지는 움직임"이 서로 겹쳐서 동시에 진행되게 했다 — 이렇게 하면 두 개의 분리된 동작이 아니라 하나로 이어지는 동작처럼 느껴진다. 이 과정에서 클릭했던 카드 자신이 "일반 카드"에서 "새로운 중심 카드(허브)"로 내부적으로 교체되는 순간에도 팍 튀지 않도록, 교체되기 직전까지 커지고 있던 크기값을 그대로 새 허브에 이어받게 해서 크기가 끊기지 않고 계속 자연스럽게 이어지도록 만들었다.

**③ "데이터 로딩이 느리면 빈 껍데기부터, 이미지는 나중에"**: 확인해보니 이 사이트는 카드 내용(제목, 이미지 등)을 서버에서 실시간으로 가져오는 구조가 아니라 전부 페이지에 미리 담겨 있는 정적 데이터라서, 애초에 "데이터 로딩이 느려서 위치 잡는 게 지연되는" 상황 자체가 발생하지 않는다. 또한 카드의 위치·크기·투명도 애니메이션은 처음부터 이미지 로딩 완료 여부와 전혀 무관하게 진행되도록 짜여 있었다(이미지는 브라우저가 알아서 백그라운드로 불러오고, 카드 레이아웃은 그것과 무관하게 먼저 자리를 잡는다) — 즉 요청하신 "위치부터 먼저, 이미지는 나중에" 원칙은 이미 지켜지고 있었다. 새로 만들 필요는 없었지만, 앞으로 이 부분을 건드릴 일이 생기면 이 원칙을 반드시 유지해야 한다.

**검증**: 화면 컨테이너의 실제 회전값을 첫 진입 시점부터 직접 측정해, 이전에는 비어 있다가(회전 없음) 1.2초 뒤 처음 값이 채워지던 것이 수정 후에는 처음부터 올바른 값으로 채워져 있음을 확인. 그룹 카드를 클릭한 뒤 하부 카드 하나를 프레임 단위로 추적해 실제로 중심에서 0으로 시작해 서서히 자리를 잡아가며 불투명도도 0→0.43→0.87로 점진적으로 올라가는 것을 정밀 측정으로 확인(약 400ms에 걸쳐 실제로 진행됨 — 순간적으로 팍 나타나는 게 아님). 클릭 직후 커지고 있던 카드의 크기값이 화면 재구성 시점에도 끊기지 않고 이어짐을 확인. 전환 도중 스크린샷으로 "커지고 있는 중심 카드"와 "펼쳐지고 있는 하부 카드들"이 동시에 함께 보이는 것을 시각적으로 확인. 상단 클릭 진입, 배경 카드 클릭 진입, 말단 카드 포커스/해제, 완전한 뒤로가기까지 포함한 전체 과정을 3회 반복해도 전부 콘솔 에러 없이 정상 동작함을 확인.

### 레벨 전환을 "다 지우고 새로 그리기"에서 "같은 카드를 진짜로 재사용해 이동"하는 방식으로 전면 재설계(2026-08-25, 같은 날 마지막 라운드)
"펼쳐진 그룹 카드를 다시 선택 시, 하부 카드들이 모이고 나서 현재 그룹 카드가 다른 그룹들 사이로 이동하는 게 있어야 돼. 그게 없다. 펼쳐져 있는 그룹 상태에서 다른 그룹을 선택 시의 전환 과정이 매끄럽지 않다. 여전히 외부에서 펼쳐지고 다시 동시에 들어온다... 무조건 매끄럽게 전체가 움직이는 과정이 다 보여야 된다. 그게 대전제야."

**원인**: 지금까지는 그룹을 열거나 닫을 때마다 화면에 있던 카드들을 전부 지우고 처음부터 다시 그리는 방식이었다. 계속 남아있어야 할 카드(예: 상위 그룹들, 방금까지 중심이었다가 이제 일반 카드가 되는 카드)도 예외 없이 "일단 사라졌다가 다시 옅게 나타나는" 식으로 처리되고 있었던 것 — 이게 "바깥에서 펼쳐지고 다시 들어온다"는 끊기는 인상의 진짜 원인이었다. 특히 방금까지 중심 카드였던 것이 접힐 때 그냥 사라지고 다른 곳에 새 카드가 옅게 나타나는 식이라, "그 카드가 이동한다"는 느낌 자체가 없었다.

**수정**: 화면이 바뀔 때마다 "이 카드, 이전 화면에도 있었나?"를 먼저 확인해서, 있었다면 화면 요소 자체를 그대로 재사용해 새 위치로 부드럽게 이동시키고(불투명도가 한 번도 0으로 떨어지지 않음 — 사라지는 순간이 아예 없음), 처음 보는 카드만 허브에서 튀어나오듯 새로 나타나게 했다. 특히 그룹을 접을 때 방금까지 중심이었던 카드는, 사라지는 대신 "일반 카드로 변신해서 다른 그룹들 사이 자기 자리로 실제로 이동하는" 모습이 보이게 됐다 — 요청하신 바로 그 동작이다. 다른 그룹으로 옮겨갈 때도, 계속 남아있는 상위 그룹 카드들이 사라졌다 다시 나타나지 않고 그 자리에서 매끄럽게 재배치된다.

**검증**: 그룹을 접을 때 방금까지 중심이었던 카드를 이름으로 추적해 매 프레임 상태를 기록한 결과 — 불투명도가 처음부터 끝까지 단 한 번도 0이 되지 않고 "1"로 유지됐고, 크기는 실제로 1.85배(중심 카드 크기)에서 1배(보통 카드 크기)로, 위치는 화면 중앙(0)에서 다른 카드들 사이(약 162px 떨어진 위치)로 부드럽게 이동하는 것을 확인했다. 다른 그룹으로 옮겨갈 때는 화면 요소 자체가 진짜로 재사용되는지(단순히 비슷해 보이는 게 아니라 완전히 같은 객체인지) 직접 확인했다 — 19개 카드 중 6개(공통 상위 그룹들)가 정확히 동일한 화면 요소로 유지됨을 확인했고, 완전히 다른 가지로 건너뛴 경우 이전 중심 카드는 정상적으로(옅어지며) 사라지는 것도 함께 확인했다. 상단 클릭 진입·배경 카드 클릭 진입·말단 카드 포커스/해제·완전한 뒤로가기를 포함한 전체 과정을 3회 반복해도 그리드·카드 밝기가 항상 정상 범위로 유지되고 콘솔 에러 없이 통과함을 확인.

### 홈페이지 첫 진입 시 가상 공간 모드를 랜덤하게 선택(2026-08-25, 같은 날 마지막 라운드)
"홈페이지가 시작할 때 가상 화면을 랜덤하게 올려 줘." 지금까지는 항상 도넛 브라우저(1번 모드)로 시작했는데, 페이지를 새로 열 때마다 도넛 브라우저와 인터랙티브 네트워크 중 하나를 무작위로 골라 먼저 보여주도록 바꿨다. 이후 모드 전환 버튼으로 오가는 동작은 기존과 동일하다.

인터랙티브 네트워크가 "첫 화면"으로 뜨는 경우는 지금까지 한 번도 실제로 일어난 적이 없던 경로였다(항상 토글 버튼을 눌러서, 즉 전환 애니메이션을 거쳐서만 들어갔었음) — 그래서 이 경로도 별도로 새로 검증했다. 페이지를 12번 새로 열어 도넛/네트워크가 각각 첫 화면으로 뜨는 것을 모두 확인했고, 네트워크가 첫 화면일 때도 카드·연결선·궤도 회전이 전부 정상적으로 초기화됨을 확인했으며 콘솔 에러도 없었다.
- **카드 화면 흐림의 진짜 원인**: "아까 블러처리 오류 수정했다고 하나, 여전히 카드 화면이 흐리다." 이전에 제거한 CSS 블러 효과는 실제로 있던 문제였지만 전부는 아니었다 — 네트워크 카드가 데이터 월(아카이브) 그리드용으로 압축된 저용량 이미지(`art-XX.webp`)를 쓰고 있었던 게 남은 원인이었다. 확인해보니 원본과 픽셀 해상도(1254×1254)는 같았지만 압축 품질이 더 낮아(같은 이미지 기준 약 138KB vs 204KB) 카드 크기로 확대해서 보면 부드럽게 뭉개져 보였다. 도넛 브라우저 카드가 원래 쓰고 있던 고화질 원본(`original-XX.webp`)으로 교체해 선명하게 만들었다.

### 랜덤 초기 모드 도입 후 "그리드가 깨진다"(2026-08-25, 같은 날 마지막 라운드)
"랜덤 기능을 넣고 나니까 그리드가 깨진다." Playwright로 네트워크 모드가 첫 화면으로 뜨는 경로를 직접 조사해 카드·연결선의 인라인 `opacity`가 빈 문자열(`""`)로 남아있는 걸 확인 — 즉 실제로 투명도 값이 아예 설정되지 않은 상태였다.

**원인**: 바로 앞 라운드("레벨 전환을 재사용 방식으로 전면 재설계")에서 DOM 요소를 새로 만드는 부분(`renderNetworkDom()`)을 고치면서, 새로 생기는 카드·연결선에 초기 `opacity`를 실제로 적어주는 코드 한 줄이 실수로 빠졌다(내부 장부 값(`dataset.baseOpacity`)만 남기고). 지금까지 이 버그가 안 보였던 건 도넛↔네트워크 전환, 그룹 진입/뒤로 가기 등 지금까지 네트워크 모드로 들어가는 모든 경로가 전부 자기 나름의 등장 애니메이션(흩어졌다 모이기, 페이드인 등)을 갖고 있어서 그 안에서 opacity를 다시 한번 명시적으로 지정해줬기 때문 — 유일하게 아무 애니메이션도 없이 "그냥 딱 그려지는" 경로가 이번에 새로 추가된 "페이지를 열자마자 네트워크 모드로 바로 시작"뿐이었고, 그 경로에서만 이 빠진 opacity 설정이 그대로 드러났다.

**수정**: 새로 만들어지는 카드·연결선에는 만들어지는 즉시 올바른 초기 투명도 값을 명시적으로 적어주도록 복원(기존 요소를 재사용하는 경우는 건드리지 않음 — 재사용 요소는 자기 "이전" 투명도를 그대로 유지해야 전환 애니메이션이 정상 작동하므로).

**검증**: Playwright로 네트워크 모드가 첫 화면으로 뜰 때까지 반복 새로고침(3회) → 매번 카드·연결선 opacity가 정상 값(`"1"`/`"0.85"` 등)으로 설정됨을 확인, 콘솔 에러 0건. 이어서 리프 포커스, 그룹 진입, 배경 카드 클릭, 뒤로 가기를 3회 반복하는 회귀 테스트도 실행해 opacity가 매 사이클 동일하게 안정적임을 확인(`edges: 0.85`, `cards: 1`, 스택 길이 정상 복귀) — 이번 수정이 앞서 완성된 "요소 재사용" 애니메이션 체계를 깨뜨리지 않았음을 함께 확인함.

**⚠️ 이 검증은 불충분했음 — 사용자가 직접 지적**: "그리드가 깨지는 경우는 띄우고 나서 가상 화면을 전환하면 깨지는데, 그걸 확인한 거야? 아니면 처음에 그냥 띄워보기만 한 거야? 그냥 띄워보기만 할 때에는 안 깨져." 위 검증은 전부 "페이지를 새로 열 때" 케이스만 반복한 것이었고, 사용자가 실제로 말한 재현 경로("띄우고 나서 전환")는 한 번도 직접 테스트하지 않았다. 정확한 재현 경로로 다시 확인하자 **완전히 다른, 더 심각한 실제 버그**를 발견했다 — 아래 새 항목 참고.

### "그리드가 깨진다"의 진짜 원인 — 모드를 전환할 때마다 고아 DOM 요소가 계속 쌓임(2026-08-25, 같은 날 마지막 라운드)
사용자가 지적한 정확한 재현 경로(페이지 로드 → 가상 모드 토글 버튼으로 전환 → 다시 전환)로 직접 재현·측정: 네트워크 모드로 시작 → 도넛으로 전환 → 다시 네트워크로 전환, 딱 한 번의 왕복 후 실제 카드 DOM 개수(`button.network-node`)는 24개인데 코드가 실제로 추적/제어하는 카드 배열(`networkNodes`)은 8개뿐이었다. 즉 16개는 화면 어딘가에 마지막으로 그려졌던 위치에 그대로 얼어붙어 남아있는 "유령 카드/연결선"으로, 매 프레임 위치를 다시 계산해주는 로직의 손이 전혀 닿지 않는 상태였다 — 이게 화면에 뒤엉킨 카드·엉뚱한 연결선으로 보이며 "그리드가 깨진다"로 인식된 것.

**원인**: 그룹 진입/뒤로 가기(`pushNetworkLevel`/`backNetworkLevel`)는 화면을 다시 그리기 전에 항상 "지금 화면에 뭐가 떠 있는지" 스냅샷을 찍어 넘겨줘서, 다시 그릴 때 안 쓰는 옛 요소를 정리(삭제)하고 살아남는 요소는 재사용한다. 그런데 **가상 모드를 껐다 켤 때 호출되는 두 곳(모드 진입 시 `ensureNetworkBuilt()`, 모드 이탈 직전 재동기화 코드)은 이 스냅샷을 넘기지 않고 있었다** — 스냅샷이 없으면 화면 정리(옛 요소 삭제) 로직 자체가 통째로 건너뛰어지도록 짜여 있었기 때문에, 전환할 때마다 기존 카드·연결선은 그대로 남겨둔 채 완전히 새로운 세트를 통째로 새로 만들어 덧붙이기만 했다 — 왕복할수록 유령 요소가 계속 누적되는 구조였다.

**수정**: 두 호출 지점 모두 스냅샷을 찍어 넘기도록 수정(`syncNetworkCurrent(snapshotNetworkScene())`) — 페이지를 처음 열 때는 아직 카드가 하나도 없으니 빈 스냅샷이라 기존과 동일하게 동작하고, 그 이후 모든 전환에서는 그룹 진입/뒤로 가기와 똑같은 방식으로 옛 요소를 정리하고 살아남는 요소는 재사용하게 됨.

**검증**: 네트워크 모드로 시작해 토글 버튼을 6번 눌러(왕복 3회) 매번 실제 DOM 카드/연결선 개수가 코드가 추적하는 개수와 정확히 일치함을 확인(8=8, 유령 요소 0개). 더 까다로운 시나리오로 그룹 하나에 진입해 있는 상태(계층 2단계 깊이)에서 왕복 전환을 2회 반복해도 매번 정확히 일치(19=19, 허브 포함), 이어서 뒤로 가기까지 실행해도 최상위 8개로 정상 복귀함을 확인. 스크린샷으로도 유령 카드나 엉뚱하게 뻗은 연결선 없이 깔끔하게 보임을 확인, 콘솔 에러 0건.

### 모바일에서 상하 스와이프 시 화면 자체가 스크롤됨(2026-08-25, 같은 날 마지막 라운드)
"모바일 화면에서 상하로 손가락으로 스와이프할 경우, 화면 자체가 스크롤 돼버린다." 원인은 CSS `touch-action` 속성 — `.network-shell`(인터랙티브 네트워크 모드 영역)에 `touch-action:pan-y`(세로 방향은 브라우저의 기본 페이지 스크롤에 맡기고, 가로 방향만 우리 코드가 가로채 쓰겠다는 설정)가 걸려 있었다. 이 설정은 2026-08-01, 도넛 브라우저(가로 회전만 가능)를 만들 때 정해진 값을 네트워크 모드를 새로 만들면서 그대로 복사해 온 것 — 도넛은 가로로만 도는 게 맞아서 세로 스와이프는 페이지 스크롤에 넘겨주는 게 원래 의도대로 맞지만, 그 후 네트워크 모드에는 세로 방향 카메라 회전(위아래로 훑어보기)이 추가됐는데도 이 낡은 설정이 그대로 남아있어서, 손가락으로 위아래로 밀면 정작 화면 안의 3D 회전은 전혀 반응하지 않고 브라우저가 그 제스처를 그냥 "페이지를 스크롤하라"는 뜻으로 먼저 가로채 버린 것이었다.

**수정**: `.network-shell`의 `touch-action`을 `pan-y`에서 `none`으로 변경 — 이 영역 안에서는 가로·세로 모든 방향의 스와이프를 브라우저가 가로채지 않고 전부 우리 코드(카메라 회전 로직)가 직접 처리하도록 함. 이미 같은 방식으로 동작 중인 원본 뷰어의 확대/이동 영역과 동일한 설정이다. 도넛 브라우저(`.torus-shell`)는 원래 의도대로 가로 회전만 지원하므로 건드리지 않음 — 세로 스와이프는 여전히 페이지 스크롤로 자연스럽게 넘어간다.

**검증**: 실제 터치 입력을 흉내 내는 정확한 방법(Chrome DevTools Protocol의 터치 이벤트 디스패치 — 자바스크립트로 직접 만든 가짜 터치 이벤트는 브라우저의 터치 제스처 인식 자체를 우회해버려서 이런 버그를 못 잡아낸다는 걸 확인 후 방법을 바꿈)으로 모바일 화면 크기에서 확인: 네트워크 모드에서 위로 스와이프 시 카메라 각도(피치)가 실제로 바뀌고(-8°→약 71°) 페이지 스크롤 위치는 그대로(0) 유지됨을 확인; 도넛 모드로 전환해 같은 스와이프를 해보면 여전히 페이지가 정상적으로 스크롤됨(의도한 그대로, 회귀 없음)을 확인; 가로 스와이프(좌우 회전)와 카드 탭(그룹 진입)도 문제없이 동작함을 함께 확인.

### 모바일에서 가상화면 전환 버튼이 메뉴 버튼에 너무 붙어있음(2026-08-26)
"가상화면 전환 버튼이 모바일에서는 메뉴버튼 바로 아래에 올라붙는다. 차상위 이동 버튼과 동일 세로 위치에 넣어줘." 모바일(≤640px) 화면에서 전환 버튼의 세로 위치가 `82px`로 고정돼 있어 상단 메뉴 버튼 바로 아래 너무 가깝게 붙어 있었던 반면, "차상위로 이동" 버튼(뒤로 가기 버튼)은 실제로는 화면 실측을 바탕으로 동적으로 계산되는 훨씬 아래쪽 위치(대략 `390px` 부근, 기기별로 약간씩 다름)에 놓여 있어 둘의 높이가 크게 어긋나 있었다.

**부수 발견**: 수정하려고 보니 도넛 모드의 뒤로 가기 버튼과 네트워크 모드의 뒤로 가기 버튼조차 서로 다른 세로 위치 공식을 쓰고 있었다 — 도넛 쪽은 최근에 동적 계산 방식으로 업그레이드됐는데 네트워크 쪽은 예전의 고정값(`390px`)에 그대로 남아 있던 것. 즉 지금까지는 모드에 따라 뒤로 가기 버튼 위치 자체가 미묘하게 달랐던 셈.

**수정**: 전환 버튼과 네트워크 모드의 뒤로 가기 버튼 둘 다, 도넛 모드의 뒤로 가기 버튼이 쓰는 것과 동일한 동적 계산 공식으로 통일 — 모바일에서는 이제 어느 모드에 있든 "차상위 이동" 버튼(보일 때)과 가상화면 전환 버튼이 항상 같은 가로줄에 나란히 놓인다. 태블릿/데스크톱 폭은 이번에 문제로 지적되지 않아 건드리지 않았다.

**검증**: 도넛 모드에서 하위 그룹으로 진입해 뒤로 가기 버튼이 보이는 상태와 네트워크 모드에서 동일하게 진입한 상태 각각에서 두 버튼의 실제 화면상 세로 좌표를 측정 — 두 모드 모두 전환 버튼과 뒤로 가기 버튼의 세로 좌표가 정확히 일치함을 확인, 스크린샷으로도 나란히 놓인 모습을 확인.

## 가상 공간 모드 2 — 인터랙티브 네트워크: 태양계 궤도 모델(2026-08-23, 최종 확정)

여러 차례 재설계를 거쳐 최종적으로 "우주를 생각하면 된다 — 태양 주변을 행성이 돌고, 그 태양은 은하 주변을 돌고…"라는 사용자의 명시적 모델로 확정됨. 이전 버전들(85개 카드 평면 매핑 → 도넛과 똑같은 "탑다운 드릴다운, 클릭하면 화면이 하위 목록으로 완전히 바뀌는" 방식)은 전부 대체됨 — 아래가 현재(최종) 사양이며, 다시 손댈 때는 이 섹션만 참고하면 된다.

- **배경 투명**: `.network-shell`은 별도 배경이 없다 — 메인 히어로 그라디언트가 그대로 비침("메인 화면 바탕을 그대로 사용해달라").
- **데이터**: 도넛 브라우저(모드 1)와 완전히 동일한 계층(`torusGroups`→`childTorusItems`/`makeSubgroupItems`→`makeSubItems`)을 재사용.
- **항성-행성 구조**: `networkHub`(현재 "태양" — 최상위에서는 `null`, 그 아래로 내려가면 방금 클릭해서 들어간 그룹/하위그룹 아이템)가 있으면 화면 중앙(로컬 좌표 원점 `0,0,0`)에 확대된 "허브 카드"(`.network-hub`, 일반 노드의 `NETWORK_HUB_SCALE=1.85`배, 보라색 글로우 테두리, 클릭 불가능한 순수 장식용 `<div>`)가 렌더링된다. 최상위(허브 없음)에서는 대분류 8개가 빈 공간(우주) 안에서 그냥 서로 공전한다.
- **행성은 계속 공전한다**: 각 자식 노드는 정적 위치가 아니라 `orbitRadius`/`orbitAngle`/`orbitSpeed`(랜덤, 방향도 랜덤)/`tilt`(궤도면 기울기, 랜덤)를 갖고 **매 프레임(`networkFrame()` 안의 `advanceNetworkOrbits(1)`) 자체적으로 계속 회전**한다 — 사용자가 드래그를 전혀 안 해도 행성들이 저절로 공전한다. 카메라(드래그로 돌리는 `.network-scene`의 yaw/pitch)와는 **완전히 별개의 움직임**이며 둘 다 항상 동시에 적용됨.
- **연결선(스포크)**: 허브가 있을 때만, 허브(원점)→각 행성으로 얇은 선을 그린다(`positionNetworkEdge(div, NETWORK_ORIGIN, node)`, 기존 최근접-이웃 메시 방식은 폐기). 최상위(허브 없음)에는 선이 없다 — 빈 우주에는 아직 중심 천체가 없으므로.
- **클릭 = 그 행성 쪽으로 카메라가 이동, 카드 자신은 궤도 위치 그대로**(2026-08-25 최종 규칙 — "카드 위치 이동 금지" 절 참고): 그룹/하위그룹 레벨에서 카드를 클릭해도 그 카드는 위치·크기가 전혀 바뀌지 않고 계속 자기 궤도를 돈다. 대신 카메라(시야각)가 그 카드가 클릭된 순간의 위치를 바라보도록 매끄럽게 회전한다(`panCameraToPoint()`, `NETWORK_ENTER_MS=480ms`). 동시에 나머지 형제 카드·이전 허브는 페이드아웃 → 그 다음 그 아이템의 자식들이 새로운 궤도 행성 세트로 렌더링되며 페이드인된다(`enterNetworkNode()`→`pushNetworkLevel()`). 새 레벨의 허브는 여전히 로컬 원점 `(0,0,0)`에 렌더링되고 원점은 어떤 카메라 각도에서도 항상 화면 정중앙에 투영된다.
- **뒤로 가기(줌아웃)**: 좌상단 `#networkBack`. `fadeNetworkTo(items,mode,hub,ms)`로 전체 페이드아웃→재조합→페이드인(현재 허브와 형제들의 정확한 궤도 슬롯을 유지한 채 축소하는 정밀 애니메이션은 구현하지 않고, 단순 크로스페이드로 처리 — 복잡도 대비 이득이 적어 의도적으로 단순화함).
- **리프(개별 작품) 레벨**: 여전히 2클릭 방식 유지 — 첫 클릭은 그 카드를 허브 위치로 확대만(`focusNetworkNode()`, `networkFocusedIndex`로 상태 추적), 같은 카드를 다시 클릭해야 `openModal()`(원본 뷰어)이 열린다. `item.profile`(회사 소개 항목)은 클릭 시 `#company`로 스크롤.
- **카드 모양**: 라운드 직사각형(96×128px 데스크톱), 빌보드(각 카드가 부모 씬 회전의 역행렬만큼 스스로 반대 회전해서 항상 카메라를 정면으로 바라봄, `applyNetworkBillboard()` — 수학: 자식 회전행렬 = 부모 회전행렬의 역행렬, `Ry(-yaw)·Rx(-pitch)`).

### 이 버전에 남아있는 이전 트랩들 (계속 유효)
1. `user-select:none`/`-webkit-user-drag:none`/`-webkit-tap-highlight-color:transparent`을 `.network-shell`/`.network-node`/이미지에 걸어둠 — 없으면 드래그 중 브라우저 기본 선택 하이라이트가 파란 틴트로 화면을 덮는다.
2. `startNetworkDrag()`에서 네이티브 `e.target.closest('.network-node')`가 극단적 회전 각도에서 실패할 수 있어 `networkNodeAtPoint()`(모든 노드의 `getBoundingClientRect()`를 직접 대조하는 자체 폴백)를 항상 같이 둔다.
3. `pointerdown` 시점에 클릭 대상을 미리 저장(`networkDownIndex`)하고 `pointerup`에서 `e.target`을 다시 안 쓴다 — `setPointerCapture` 때문에 필수(도넛의 `torusDownIndex`와 동일 패턴).

## 가상 모드 간 전환 연출 — 순차 "해쳐 모여" → 겹쳐서 이어지는 크로스페이드로 재구조화(2026-08-25 최종)

우상단 모드 전환 버튼을 누르면 카드들이 흩어져 화면 밖으로 사라졌다가, 새 모드의 카드들이 다시 나타나 재조합된다. 버전이 여러 번 바뀌었다(①완전 사라짐 → ②화면 안 머무름+스태거 → ③다시 ①로, 성능 수정) — 그런데 ③ 상태에서 개별 버그(낡은 좌표, 관성 미초기화)를 다 고쳐도 사용자가 계속 "중간 과정이 끊긴다"고 재보고했다. **진짜 원인은 개별 버그가 아니라 구조 자체**였다: "나가는 애니메이션이 완전히 끝난 뒤에야 들어오는 애니메이션이 시작"하는 순차 2단계 구조는, 아무리 다듬어도 "사라짐 → (짧은 공백) → 나타남"으로 읽힌다. **최종 수정**: 두 장면을 **동시에 겹쳐서** 보여주는 진짜 크로스페이드로 재구조화 — `#spatialIntro`에 `.spatial-overlap` 클래스를 걸어 전환 중엔 도넛/네트워크 셸을 강제로 둘 다 보이게 하고, `scatterOut`(나가는 장면)과 `scatterIn`(들어오는 장면, 준비된 직후 같은 실행 틱에서 바로 시작)을 **간격 없이 동시에** 발동시킨다. 두 애니메이션이 ~450ms 동안 실제로 화면에 함께 보이는 구간이 생겨야 "연결된다"는 인상을 준다는 게 핵심 교훈 — 각 단계 자체의 정확성만 고쳐서는 부족했다.

- **오케스트레이터**: `transitionSpatialMode()`(토글 버튼 클릭 핸들러 겸 최고 속도 자동전환의 호출 대상) — 드래그 플래그와 회전 관성을 모두 초기화 → `.spatial-overlap` 추가(양쪽 셸 강제 노출) → `scatterOut(420ms)` 시작 → **곧바로 같은 틱에서** 모드 전환(`applySpatialMode()`, 목적지 장면 재구성 포함) → `scatterIn(460ms)` 시작 → 둘 다 끝날 시간이 지나면 `.spatial-overlap` 제거+버튼 재활성화. "매번 목적지 장면을 완전히 새로 재구성" 자체는 예전과 동일하게 필수(그래야 `scatterIn`이 읽는 "자연 위치"가 정확함) — 달라진 건 그 재구성과 화면 노출의 **타이밍**뿐이다.
- **확장 가능한 구조는 유지**: `spatialModeTransitions={torus:{...},network:{...}}` 룩업 테이블, 세 번째 모드가 생기면 항목만 추가하면 됨.
- **거리/투명도**: `SPATIAL_SCATTER_DIST=1700px`(화면 밖으로 확실히 나가는 거리)로 밀어내며 opacity도 `0`으로 페이드 — "화면에서 안 보였다가 다시 나타나는" 느낌을 명시적으로 요청받아 원복.
- **성능(끊김/멈춤 현상) 수정**: 이전 버전은 카드마다 개별적으로 `void el.offsetWidth`(강제 리플로우)를 호출해서, 카드 수만큼 레이아웃 재계산이 반복되며 버벅임이 났다. **모든 카드의 "시작(흩어진) 상태" 스타일을 먼저 한 번에 다 세팅한 뒤, 리플로우는 컨테이너에 대해 딱 한 번만 강제**(`void torusScene.offsetWidth` 또는 `void networkScene.offsetWidth`)하고, 그 다음에 전체 카드에 트랜지션+목표(자연) 상태를 한 번에 세팅하는 "읽기/쓰기 배치(batch)" 패턴으로 변경. **DOM 스타일을 여러 개 순회 변경할 때 강제 리플로우가 필요하면 항상 컨테이너 레벨에서 한 번만 트리거할 것 — 요소마다 트리거하면 반드시 버벅인다.**
- 스태거·팝 스케일·바운스 이징은 전부 제거(성능·"무미건조함" 둘 다 스태거보다 "화면 밖으로 사라졌다 나타나는" 원래 스타일 자체가 만족스럽다는 판단, 단순한 `ease-in`/`ease-out`으로 회귀).
- **모드 전환 버튼 아이콘 교체(2026-08-25, 3차 개선까지)**: 1차 비스듬한 3D 타원 → 2차 "3등분 원+화살표"(사용자 요청대로) → 3차 세부 다듬기("틈이 안 보인다", "화살표 머리가 너무 크다·안 이쁘다", "원을 조금 더 크게"): 원 반지름과 SVG 렌더 크기를 키우고, 호 90°·간격 30°로 틈을 더 뚜렷하게 벌리고, 화살촉을 뭉툭한 삼각형 대신 작고 날렵한 노치형 모양으로 교체, 두께도 살짝 줄여 균형을 맞췄다. 3개의 호 경로가 SVG `<marker>` 하나(`orient="auto"`로 경로 접선 방향에 자동 정렬)를 공유해 화살촉 각도를 일일이 계산할 필요가 없었다. `stroke/fill="currentColor"`로 버튼의 기존 hover 색상 전환을 그대로 물려받는다.
- **렌더 루프 충돌 방지**(계속 유효): `spatialTransitionActive` 전역 플래그를 `spatialFrame()`/`networkFrame()` 맨 앞에서 확인, 드래그 시작 함수에도 동일 가드.

### 버그: "카드가 1장만 남을 때가 있다" — 진짜 원인은 원본 뷰어(모달)가 열려 있는 상태에서의 전환
1차 수정("리프 포커스 중 opacity가 안 지워짐")으로는 부족했고, **Playwright로 집요하게 재현한 끝에 진짜 원인을 찾음**: 원본 이미지 뷰어(`.modal.open`)가 열려 있는 동안 배경의 도넛/네트워크는 계속 관성으로 돌고 있는데(모달이 열려도 `spatialFrame()`/`networkFrame()`이 안 멈춤), 그 잔여 관성이나 자동전환 임계값을 넘기거나 사용자가 실수로 버튼을 누르면 **모달이 화면을 덮고 있는 동안 뒤에서 `transitionSpatialMode()`가 실행**된다 — 이 상태에서의 흩어짐/재조합 연출·리빌드는 사용자가 보지 못하는 상태에서 꼬여서, 모달을 닫고 나면 카드 대부분이 사라진 채로 발견된다(재현: 리프 카드를 두 번 클릭해 모달을 연 뒤 모드 토글 버튼을 누르면 100% 재현). **수정**: `transitionSpatialMode()` 맨 앞에 `if(modal.classList.contains('open'))return`을 추가 — 원본 뷰어가 열려 있으면 수동 버튼도 자동 폭발도 아예 아무 일도 안 일어난다(뷰어를 닫은 뒤에는 정상 동작). Playwright로 "드릴다운→포커스→모달 열기→토글 시도(차단 확인)→모달 닫기→토글(정상 동작 확인)"을 4라운드 반복 검증, 매번 카드 전부 정상 표시됨. **교훈**: 배경에서 계속 도는 애니메이션/전환 시스템이 있으면, 그 위를 덮는 다른 풀스크린 UI(모달 등)가 열려 있는 동안에도 배경 트리거가 계속 발동할 수 있다는 걸 잊기 쉽다 — "지금 사용자가 실제로 이 화면을 보고 있는가"를 명시적으로 확인하는 가드가 필요.
- 상하 회전 180도 제한도 이 라운드에 같이 제거됨 — `dragNetwork()`/`networkFrame()`의 `networkPitch` 클램프(`±75°`)를 완전히 삭제, 이제 좌우처럼 무제한 회전.

### 최고 속도 회전 시 자동 모드 전환("폭발")
`spatialFrame()`/`networkFrame()`의 관성 분기 안에서 속도가 임계값을 넘으면 `transitionSpatialMode()`를 그대로 호출(버튼과 동일한 연출). 처음 잡은 임계값(도넛 `.22`, 네트워크 `30`)이 실제 사용해보니 잘 안 터진다는 피드백으로 **`torusVelocity>.12`(반경/확대 부스트가 최대치에 도달하는 지점 `|v|≈.16`보다 오히려 낮춤 — 실사용 체감상 이전 값은 너무 안 터졌음), `Math.hypot(networkVelocityYaw,networkVelocityPitch)>16`**로 낮춤. 손을 뗀 뒤 관성 단계에서만 발동(드래그 중엔 발동 안 함, 의도적).

## 데이터 월

최종 갱신: 2026-08-23. 아래는 여러 차례 수정을 거친 현재 확정 동작이다. 다시 손댈 때는 아래 "주의사항"부터 읽는다. 상세 구현(함수명, 정확한 상수 위치)은 Claude 메모리(`archive-wall-magnet-system`)에 압축 정리되어 있음 — 큰 수정 전에 그쪽도 같이 참고할 것.

- 홈 전용 이미지 폴더 `public/hero`는 데이터 월 수집 대상이 아니다.
- 카테고리 필터 칩(`전체`, `AI 모델`, `뷰티 광고` 등)이 제목 옆에 있다. `torusGroups`에서 자동으로 뽑은 목록이라 카테고리가 바뀌어도 따로 손볼 필요 없다.
- **마우스 오버 마그넷 효과**와 **슬립 모드(유휴 시 자동으로 카드가 옮겨 다니며 반짝이는 것)**는 같은 하나의 렌더 엔진(`renderArchiveMagnet`)을 공유하되, 슬립 모드의 "카드가 부풀어 오르는 것" 자체는 독립된 타이머(카드가 리드를 맡는 그 순간 한 번만 시작, 이후 리드가 다른 카드로 넘어가도 자기 타이밍대로 끝까지 진행)로 분리되어 있다. 절대 렌더 엔진 자체를 두 개로 다시 분리하지 않는다 — 분리할 건 "타이밍 소스"뿐이다.
- 포커스 카드는 제자리에서 위로 솟구치듯 커지기만 한다(중심 기준, 수직 이동·비틀림 없음). 크기 1.42배, 화면 쪽으로 카드폭의 0.7배만큼 튀어나옴.
- 포커스를 잃은 카드는 하단이 아니라 중심 기준으로 원래대로 돌아가며, **거리가 아니라 시간(840ms)** 기준으로 감쇠한다 — 마우스가 그 자리에 계속 머물러 있어도 시간이 지나면 무조건 원위치로 돌아간다.
- **(실제 마우스 호버 전용)** 포커스가 다른 카드로 넘어가면 새 카드는 즉시 반응하고, 주변 카드에는 거리에 비례한 지연(물결)을 준 뒤 역시 840ms에 걸쳐 원위치로 감쇠한다(이미 감쇠 중인 더 큰 값을 새 잔상값으로 깎아내리지 않음, 더 강할 때만 갱신). **슬립 모드에서는 이 주변 물결 효과가 꺼져 있다** — 포인터가 실제로 지나간 카드만 커졌다 꺼지고, 지나가지 않은 카드는 전혀 변화 없다(사용자 요청으로 명시적으로 끔).
- **슬립 모드 자동 이동은 세 가지 속도가 서로 독립적으로 조절된다**: ① 리드(포커스) 전환 주기 — 현재 248ms마다 다음 카드로(2026-08-23 사용자 요청으로 기존 124ms에서 절반 속도로 늦춤; PC/모바일이 같은 `setInterval` 한 줄을 공유하고 기기별 분기가 전혀 없어 두 화면에 동일하게 적용됨). ② 카드가 부풀어 오르는 속도 — 현재 500ms(리드가 이미 다음 카드로 넘어간 뒤에도 자기 타이밍대로 끝까지 부풂 → 여러 카드가 동시에 겹쳐서 물결처럼 보임, 리드 주기가 늘어난 만큼 동시 확인되는 카드 수는 기존보다 줄어듦). ③ 잦아드는 속도 — 840ms(마우스 호버와 공유, 이번 조정에서 건드리지 않음). 다시 조정 요청이 오면 이 세 숫자만 건드리면 되고 서로 맞출 필요 없다.
- 카드를 클릭하면 원본 보기로 들어가기 전에 **현재 화면에 보이는 카드만** 클릭한 카드 위치로 모여든다. 크기는 줄어들지 않고(클릭 직전 마그넷으로 커져 있었다면 그 크기 그대로) 위치만 이동하며, 클릭한 카드가 항상 맨 앞·맨 위(z-index와 실제 3D 앞쪽 돌출 모두)에 남고 나머지는 그 뒤로 겹쳐 들어간다. 가까운 카드가 먼저 도착하고 먼 카드는 거리 비례로 늦게 도착한다.
- 모두 모인 뒤에는 클릭한 카드 하나가 화면을 거의 채울 만큼(뷰포트 높이의 85%·너비의 56% 중 작은 쪽 기준) 커지고 나서야 실제 원본 보기가 열린다 — 마치 그 썸네일이 그대로 원본 화면이 되는 것처럼 보이게 하기 위함이다. 화면 밖·필터로 숨겨진 카드는 건드리지 않는다.
- 원본 보기를 닫으면 반대 순서로 진행된다: 커졌던 카드가 먼저 원래 썸네일 크기로 줄어들고, 그 다음에야 모여있던 카드들이 원위치로 흩어진다(동시에 일어나지 않는다).
- 필터 버튼은 제목("데이터 월에서") 바로 옆에 배치한다(PC는 한 줄, 모바일은 폭이 부족하면 제목 아래로 자동 줄바꿈). "선택 시 원본 이미지로 보입니다" 안내 문구는 사용자 요청으로 완전히 제거했다 — 되살리지 않는다.
- 필터 칩과 각 카드 좌하단 마커는 카테고리별 고유 색상을 갖는다(`archiveCatColors`, 라벨→hex 맵 하나로 관리). **배경은 절대 채우지 않고 완전 투명이 확정 사양이다** — 테두리(필터 버튼)와 글자색으로만 구분한다. 텍스트 그림자 같은 배경 대체 효과도 넣지 않는다(옅게라도 어두운 배경이 보이면 안 된다는 게 사용자의 명확한 요구사항이었고, 실제로 배경 채움→반투명→그림자 순으로 여러 번 되돌린 이력이 있다).
- 모바일에서는 공간 절약을 위해 필터 버튼 텍스트를 축약한다(각 분류 첫 글자, 단 "AI 모델"은 예외로 "AI"). PC는 축약 없이 전체 명칭을 그대로 쓴다 — 색상 자체는 PC/모바일 공통이고, 축약 여부만 `@media(max-width:640px)`로 전환된다.
- 모바일 원반 메뉴 "모두 보기" → 데이터 월 스크롤 이동은, 포트폴리오 섹션(`#portfolio`, 데이터 월 바로 위)의 카드 이미지 실제 가로세로 픽셀 크기를 `mediaMarkup()`의 `artAspect` 맵을 통해 `width`/`height` 속성으로 미리 박아 넣어 해결했다(자세한 근본 원인은 아래 주의사항 참고).

### 주의사항 (다시 걸리기 쉬운 함정)

- `.archive-thumb:hover{...}` 같은 예전 CSS 규칙을 되살리지 않는다 — 인라인 스타일(JS)이 항상 CSS 클래스보다 우선하는데, 그 반대로 착각하기 쉽다.
- `resetArchiveMagnet()`은 모든 카드의 인라인 스타일을 즉시 지운다. 데이터 월의 `pointerdown`/`pointerup`/`pointercancel` 리스너는 반드시 `pointerType==='touch'`일 때만 이 함수를 불러야 한다 — 아니면 마우스 클릭 시 `click` 이벤트가 뜨기 전에 `pointerup`이 먼저 커진 크기를 지워버린다.
- `.archive-wall`에 `transform-style:preserve-3d`가 걸려 있어서, 카드를 맨 앞에 두려면 z-index만으로는 부족하다. 실제로 카드를 화면 쪽으로 더 튀어나오게(`--mag-z`)도 해야 하고, 그 값은 항상 `Math.max(현재값, 최소값)`으로 올리기만 해야 한다(내리면 원근 계산 때문에 크기도 같이 작아 보인다).
- `measureArchiveMagnet()`(위치 재측정)은 항상 `resetArchiveMagnet()`/`freezeArchiveMagnet()`보다 **뒤에** 호출한다. 반대로 하면 방금 측정한 값을 스스로 지워버린다.
- 검증 시 Playwright로 헤드리스 크롬을 직접 띄워 테스트했는데, `mouse.move`/`click` 같은 호출 자체에 90~170ms 이상의 지연이 있어서 `waitForTimeout` + 스크린샷 방식은 타이밍을 오판하기 쉽다. `performance.now()` 기반의 페이지 내부 프레임 대기와 `--mag-*` 커스텀 프로퍼티 직접 읽기가 더 정확했다.
- 모바일 "모두 보기" 스크롤이 데이터 월 대신 포트폴리오 중간쯤에 도착하는 버그는 스크롤 오프셋 계산이 아니라 **레이아웃 자체가 아직 확정되지 않은 상태에서 위치를 쟀기 때문**이었다. `.work img`가 `loading="lazy"`이고 예약된 크기(`width`/`height` 속성이나 CSS `aspect-ratio`)가 전혀 없으면, 이미지 바이트가 도착하기 전엔 브라우저가 그 카드의 실제 높이를 모른다 — 그 상태에서 목표 지점을 계산해 스크롤하면 이미지가 나중에 로드되며 섹션 키가 늘어나 목표가 더 아래로 밀린다. `ResizeObserver`로 사후에 쫓아가며 보정하는 방식은 실제 페이지 로드 직후 클릭 같은 상황에서 여전히 실패했다(네트워크가 느리면 보정 시간 안에 다운로드 자체가 안 끝남). **근본 해결은 이미지가 도착하기도 전에 정확한 박스 크기를 브라우저에 알려주는 것**(실제 픽셀 크기를 `width`/`height` 속성으로 미리 지정) — 목표 지점을 스크롤 시작 전에 이미 정확하게 만들어서, 사후 보정 자체가 필요 없어지게 하는 게 핵심이었다. 비슷한 증상(스크롤 목표가 lazy 이미지 그리드 바로 다음 섹션인데 자꾸 짧게 도착)을 다시 보면 스크롤 오프셋 계산보다 이미지 박스 크기 예약 여부부터 의심할 것.
- 새 art 번호를 포트폴리오/데이터 월에 추가할 때는 `mediaMarkup()`의 `artAspect` 맵에도 실제 원본 가로세로 픽셀 크기(`sharp`로 읽으면 됨)를 같이 추가해야 한다. 빠뜨리면 그 이미지만 다시 레이아웃-밀림(CLS) 문제가 재발한다.
- 원본 보기를 닫을 때 접근성을 위해 포커스를 "열기 전 요소"로 되돌리는데, 그게 방금 클릭한 카드 자신이라 데이터 월의 `focusin` 리스너가 다시 발동해 "사용자가 상호작용 중"이라는 상태가 영구히 켜진 채로 남아 슬립 모드가 다시는 안 도는 버그가 있었다(수정 완료). 비슷하게 "닫을 때 포커스를 되돌리는" 코드를 다시 만질 일이 있으면, 그 포커스 대상이 데이터 월 안쪽 요소일 수 있다는 점을 염두에 둘 것.
