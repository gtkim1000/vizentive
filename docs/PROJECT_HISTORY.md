## 도넛 브라우저 동작

- 마우스 드래그 및 모바일 스와이프로 회전한다.
- 전면이 아닌 이미지를 선택하면 전면으로만 이동한다.
- 최전면 대표 이미지를 선택하면 하부 이미지로 들어간다.
- 최전면 하부 이미지를 선택하면 고해상도 원본 보기로 들어간다.
- 최전면 이미지는 조금 더 크게 표시한다.
- 후면 이미지도 흐리게 만들지 않고 최대한 선명하게 표시한다.
- 대표 이미지 설명은 대분류 상태에서만 표시한다.
- **회전 속도 연동 반경 확대 + 카드 확대, 최종 확정 동작(2026-08-23)**: 빠르게 드래그해서 돌릴수록 ① 카드들 사이의 **가로 간격**(원심력처럼, `rx`만)이 최대 **200%**(`torusSpinRadiusBoostMax=1`)까지 벌어지고, ② 카드 자체의 **확대(스케일)**도 별도로 최대 **130%**(`torusSpinScaleBoostMax=.3`, `.1`→`.2`→`.3`으로 재조정, `compositeScale`에 곱함)까지 커진다 — 이 둘은 서로 독립된 상태값(`torusRadiusBoost`/`torusScaleBoost`)이며 `layoutTorus()`에서 각각 적용된다. **단, 깊이(`rz`)는 절대 건드리지 않는다** — 한때 `rz`도 같이 키운 적이 있었는데, 카드가 카메라에 가까워지면서 고정된 CSS `perspective` 때문에 원근 효과로 카드가 화면을 덮을 만큼 확대되어 보이는 부작용이 있어 완전히 되돌렸다(스케일은 오직 명시적 `compositeScale` 곱셈으로만 조절, `rz`는 항상 기본값 고정). Playwright 실측: 가로 반경 배율 ~2.02배, 카드 스케일 배율 ~1.11배로 목표치와 정확히 일치, 부작용 없이 깔끔하게 동작 확인. 두 효과 모두 속도→목표값 민감도(`torusSpinRadiusBoostScale=6.25`, 공유)와 느린 복귀(각각 `torusSpinRadiusBoostFallRate`/`torusSpinScaleBoostFallRate=.01`, 관성 감쇠와 분리)를 따른다. 클릭 선택·카테고리 스냅 등 회전이 멈추는 모든 상황에서 동일하게 적용. **다시 조정 요청이 오면 각 최대치(`torusSpinRadiusBoostMax`/`torusSpinScaleBoostMax`)와 복귀 속도만 건드리고, `rz`는 절대 손대지 말 것.**
- ⚠️ 이 절의 변경들이 2026-08-23 세션 내내 아직 `main`에 커밋·배포되지 않은 상태였다(로컬 `dist/`·`localhost:8000` 기준으로만 매번 Playwright 실측 검증). 배포(`git push` → Vercel 자동 배포)는 사용자가 명시적으로 "배포해줘"라고 할 때만 진행한다는 규칙(`AGENTS.md`) 때문.
- **회전 관성(손 뗀 뒤 서서히 멈추는 것) 감쇠 속도(2026-08-23, 두 차례 조정)**: `spatialFrame()`의 `torusVelocity*=RATE`(프레임당 감쇠율)를 원래 `.94`에서 `.9695`(1차, "두 배 더 느리게")를 거쳐 최종 **`.9846`**(2차, "관성이 좀 더 오래 지속되도록, 2배 정도")로 변경 — 매번 "N배 느리게"는 `기존값**(1/N)`(= `sqrt`, N=2일 때)로 계산해서 "지수적으로 반으로 줄어드는 데 걸리는 시간(half-life)"이 정확히 N배가 되도록 함(`.94`→`.9695`→`.9846` 각 단계가 half-life 2배씩). Playwright로 `.torus-card.front`가 바뀌는 시점을 추적해 관성 지속 시간이 이전(~2.8초)보다 늘어난 것(~5.9초)을 실측 확인. 이 상수는 위 반경/확대 효과(`torusSpinRadiusBoostScale`이 이 속도값을 그대로 참조)와도 연결되어 있어, 관성이 느려지면 반경·확대가 커져 있는 시간도 자연히 함께 길어짐 — 의도된 상호작용이며 별도 보정 불필요. 다시 "더 오래/짧게 돈다"는 요청이 오면 이 감쇠율 하나만 `기존값**(1/N)` 또는 `기존값**N`으로 재계산(절대 가까운 소수점을 감으로 넣지 말 것), 관성 정지 임계값(`.00002`)은 그대로 둔다.
- **가상 공간 모드 전환 버튼(2026-08-23 추가, 스캐폴드만)**: 우상단에 항상 표시되는 원형 아이콘 버튼(`#torusModeToggle`, 글자 `⟳`)을 추가 — 좌상단의 `torusBack`(하위 그룹 진입 시에만 보임)과 달리 모드와 무관하게 **항상** 떠 있다. 클릭하면 `spatialModes=['torus','placeholder']` 배열을 순환하며 `#spatialIntro`의 `data-spatial-mode` 속성을 바꾼다(`torus`↔`placeholder`). `placeholder`가 되면 CSS로 `.torus-shell`/`.hologram`/`.torus-back`/`.scene-counter`를 숨기고 `.spatial-placeholder`("모드 2 준비 중")를 대신 보여준다 — **아직 실제 두 번째 가상 모드는 디자인되지 않았고, 사용자가 명시적으로 "버튼·전환 구조만 먼저" 만들라고 요청**해서 지금은 자리만 잡아둔 상태. 실제 두 번째 모드(어떤 3D/공간형 레이아웃일지)는 다음 요청에서 구체화 예정이며, 그때 `spatialModes` 배열에 값 하나 추가 + 해당 모드 렌더링 함수 연결로 확장하면 됨(모드 개수는 향후 더 늘어날 수 있음, 배열 기반이라 확장 용이). **자동 전환 모드(도넛을 너무 빠르게 돌리면 회전이 "터져서" 다른 모드로 자동 재조합되는 연출)는 사용자가 명시적으로 "아직 코딩하지 말아달라"고 해서 미구현** — 나중에 요청 오면 그때 설계.
- 버튼 위치는 반드시 **고정 px로 헤더(78px, 모바일 640px 이하는 70px)를 기준으로 여백을 둬야 한다** — 처음에 `top:4%` 같은 퍼센트로 배치했다가 짧은 섹션 높이에서 실제 계산값이 헤더 아래로 못 내려가 고정 헤더(`z-index:80`)가 클릭을 가로채는 문제가 있었음(Playwright로 클릭 타임아웃 발생시켜 발견). `hologram`은 `pointer-events:none`이라 시각적으로 살짝 겹쳐도 클릭은 안 막히지만, 실제 클릭 가능한 `.header`와는 항상 좌표를 띄워야 함.

## 데이터 월

최종 갱신: 2026-08-23. 아래는 여러 차례 수정을 거친 현재 확정 동작이다. 다시 손댈 때는 아래 "주의사항"부터 읽는다. 상세 구현(함수명, 정확한 상수 위치)은 Claude 메모리(`archive-wall-magnet-system`)에 압축 정리되어 있음 — 큰 수정 전에 그쪽도 같이 참고할 것.

- 홈 전용 이미지 폴더 `public/hero`는 데이터 월 수집 대상이 아니다.
- 카테고리 필터 칩(`전체`, `AI 모델`, `뷰티 광고` 등)이 제목 옆에 있다. `torusGroups`에서 자동으로 뽑은 목록이라 카테고리가 바뀌어도 따로 손볼 필요 없다.
- **마우스 오버 마그넷 효과**와 **슬립 모드(유휴 시 자동으로 카드가 옮겨 다니며 반짝이는 것)**는 같은 하나의 렌더 엔진(`renderArchiveMagnet`)을 공유하되, 슬립 모드의 "카드가 부풀어 오르는 것" 자체는 독립된 타이머(카드가 리드를 맡는 그 순간 한 번만 시작, 이후 리드가 다른 카드로 넘어가도 자기 타이밍대로 끝까지 진행)로 분리되어 있다. 절대 렌더 엔진 자체를 두 개로 다시 분리하지 않는다 — 분리할 건 "타이밍 소스"뿐이다.
- 포커스 카드는 제자리에서 위로 솟구치듯 커지기만 한다(중심 기준, 수직 이동·비틀림 없음). 크기 1.42배, 화면 쪽으로 카드폭의 0.7배만큼 튀어나옴.
- 포커스를 잃은 카드는 하단이 아니라 중심 기준으로 원래대로 돌아가며, **거리가 아니라 시간(840ms)** 기준으로 감쇠한다 — 마우스가 그 자리에 계속 머물러 있어도 시간이 지나면 무조건 원위치로 돌아간다.
- **(실제 마우스 호버 전용)** 포커스가 다른 카드로 넘어가면 새 카드는 즉시 반응하고, 주변 카드에는 거리에 비례한 지연(물결)을 준 뒤 역시 840ms에 걸쳐 원위치로 감쇠한다(이미 감쇠 중인 더 큰 값을 새 잔상값으로 깎아내리지 않음, 더 강할 때만 갱신). **슬립 모드에서는 이 주변 물결 효과가 꺼져 있다** — 포인터가 실제로 지나간 카드만 커졌다 꺼지고, 지나가지 않은 카드는 전혀 변화 없다(사용자 요청으로 명시적으로 끔).
- **슬립 모드 자동 이동은 세 가지 속도가 서로 독립적으로 조절된다**: ① 리드(포커스) 전환 주기 — 현재 248ms마다 다음 카드로(2026-08-23 사용자 요청으로 기존 124ms에서 절반 속도로 늦춤; PC/모바일이 같은 `setInterval` 한 줄을 공유하고 기기별 분기가 전혀 없어 두 화면에 동일하게 적용됨). ② 카드가 부풀어 오르는 속도 — 현재 500ms(리드가 이미 다음 카드로 넘어간 뒤에도 자기 타이밍대로 끝까지 부풂 → 여러 카드가 동시에 겹쳐서 물결처럼 보임, 리드 주기가 늘어난 만큼 동시 확인되는 카드 수는 기존보다 줄어듦). ③ 잦아드는 속도 — 840ms(마우스 호버와 공유, 이번 조정에서 건드리지 않음). 다시 조정 요청이 오면 이 세 숫자만 건드리면 되고 서로 맞출 필요 없다.
- 카드를 클릭하면 원본 보기로 들어가기 전에 **현재 화면에 보이는 카드만** 클릭한 카드 위치로 모여든다. 크기는 줄어들지 않고(클릭 직전 마그넷으로 커져 있었다면 그 크기 그대로) 위치만 이동하며, 클릭한 카드가 항상 맨 앞·맨 위(z-index와 실제 3D 앞쪽 돌출 모두)에 남고 나머지는 그 뒤로 겹쳐 들어간다. 가까운 카드가 먼저 도착하고 먼 카드는 거리 비례로 늦게 도착한다.
- 모두 모인 뒤에는 클릭한 카드 하나가 화면을 거의 채울 만큼(뷰포트 높이의 85%·너비의 56% 중 작은 쪽 기준) 커지고 나서야 실제 원본 보기가 열린다 — 마치 그 썸네일이 그대로 원본 화면이 되는 것처럼 보이게 하기 위함이다. 화면 밖·필터로 숨겨진 카드는 건드리지 않는다.
- 원본 보기를 닫으면 반대 순서로 진행된다: 커졌던 카드가 먼저 원래 썸네일 크기로 줄어들고, 그 다음에야 모여있던 카드들이 원위치로 흩어진다(동시에 일어나지 않는다).
- 필터 버튼은 제목("데이터 월에서") 바로 옆에 배치한다(PC는 한 줄, 모바일은 폭이 부족하면 제목 아래로 자동 줄바꿈). "선택 시 원본 이미지로 보입니다" 안내 문구는 사용자 요청으로 완전히 제거했다 — 되살리지 않는다.
- 필터 칩과 각 카드 좌하단 마커는 카테고리별 고유 색상을 갖는다(`archiveCatColors`, 라벨→hex 맵 하나로 관리). **배경은 절대 채우지 않고 완전 투명이 확정 사양이다** — 테두리(필터 버튼)와 글자색으로만 구분한다. 텍스트 그림자 같은 배경 대체 효과도 넣지 않는다(옅게라도 어두운 배경이 보이면 안 된다는 게 사용자의 명확한 요구사항이었고, 실제로 배경 채움→반투명→그림자 순으로 여러 번 되돌린 이력이 있다).
- 모바일에서는 공간 절약을 위해 필터 버튼 텍스트를 축약한다(각 분류 첫 글자, 단 "AI 모델"은 예외로 "AI"). PC는 축약 없이 전체 명칭을 그대로 쓴다 — 색상 자체는 PC/모바일 공통이고, 축약 여부만 `@media(max-width:640px)`로 전환된다.
- 모바일 원반 메뉴 "모두 보기" → 데이터 월 스크롤 이동은, 포트폴리오 섹션(`#portfolio`, 데이터 월 바로 위)의 카드 이미지 실제 가로세로 픽셀 크기를 `mediaMarkup()`의 `artAspect` 맵을 통해 `width`/`height` 속성으로 미리 박아 넣어 해결했다(자세한 근본 원인은 아래 주의사항 참고).

### 주의사항 (다시 걸리기 쉬운 함정)

- `.archive-thumb:hover{...}` 같은 예전 CSS 규칙을 되살리지 않는다 — 인라인 스타일(JS)이 항상 CSS 클래스보다 우선하는데, 그 반대로 착각하기 쉽다.
- `resetArchiveMagnet()`은 모든 카드의 인라인 스타일을 즉시 지운다. 데이터 월의 `pointerdown`/`pointerup`/`pointercancel` 리스너는 반드시 `pointerType==='touch'`일 때만 이 함수를 불러야 한다 — 아니면 마우스 클릭 시 `click` 이벤트가 뜨기 전에 `pointerup`이 먼저 커진 크기를 지워버린다.
- `.archive-wall`에 `transform-style:preserve-3d`가 걸려 있어서, 카드를 맨 앞에 두려면 z-index만으로는 부족하다. 실제로 카드를 화면 쪽으로 더 튀어나오게(`--mag-z`)도 해야 하고, 그 값은 항상 `Math.max(현재값, 최소값)`으로 올리기만 해야 한다(내리면 원근 계산 때문에 크기도 같이 작아 보인다).
- `measureArchiveMagnet()`(위치 재측정)은 항상 `resetArchiveMagnet()`/`freezeArchiveMagnet()`보다 **뒤에** 호출한다. 반대로 하면 방금 측정한 값을 스스로 지워버린다.
- 검증 시 Playwright로 헤드리스 크롬을 직접 띄워 테스트했는데, `mouse.move`/`click` 같은 호출 자체에 90~170ms 이상의 지연이 있어서 `waitForTimeout` + 스크린샷 방식은 타이밍을 오판하기 쉽다. `performance.now()` 기반의 페이지 내부 프레임 대기와 `--mag-*` 커스텀 프로퍼티 직접 읽기가 더 정확했다.
- 모바일 "모두 보기" 스크롤이 데이터 월 대신 포트폴리오 중간쯤에 도착하는 버그는 스크롤 오프셋 계산이 아니라 **레이아웃 자체가 아직 확정되지 않은 상태에서 위치를 쟀기 때문**이었다. `.work img`가 `loading="lazy"`이고 예약된 크기(`width`/`height` 속성이나 CSS `aspect-ratio`)가 전혀 없으면, 이미지 바이트가 도착하기 전엔 브라우저가 그 카드의 실제 높이를 모른다 — 그 상태에서 목표 지점을 계산해 스크롤하면 이미지가 나중에 로드되며 섹션 키가 늘어나 목표가 더 아래로 밀린다. `ResizeObserver`로 사후에 쫓아가며 보정하는 방식은 실제 페이지 로드 직후 클릭 같은 상황에서 여전히 실패했다(네트워크가 느리면 보정 시간 안에 다운로드 자체가 안 끝남). **근본 해결은 이미지가 도착하기도 전에 정확한 박스 크기를 브라우저에 알려주는 것**(실제 픽셀 크기를 `width`/`height` 속성으로 미리 지정) — 목표 지점을 스크롤 시작 전에 이미 정확하게 만들어서, 사후 보정 자체가 필요 없어지게 하는 게 핵심이었다. 비슷한 증상(스크롤 목표가 lazy 이미지 그리드 바로 다음 섹션인데 자꾸 짧게 도착)을 다시 보면 스크롤 오프셋 계산보다 이미지 박스 크기 예약 여부부터 의심할 것.
- 새 art 번호를 포트폴리오/데이터 월에 추가할 때는 `mediaMarkup()`의 `artAspect` 맵에도 실제 원본 가로세로 픽셀 크기(`sharp`로 읽으면 됨)를 같이 추가해야 한다. 빠뜨리면 그 이미지만 다시 레이아웃-밀림(CLS) 문제가 재발한다.
- 원본 보기를 닫을 때 접근성을 위해 포커스를 "열기 전 요소"로 되돌리는데, 그게 방금 클릭한 카드 자신이라 데이터 월의 `focusin` 리스너가 다시 발동해 "사용자가 상호작용 중"이라는 상태가 영구히 켜진 채로 남아 슬립 모드가 다시는 안 도는 버그가 있었다(수정 완료). 비슷하게 "닫을 때 포커스를 되돌리는" 코드를 다시 만질 일이 있으면, 그 포커스 대상이 데이터 월 안쪽 요소일 수 있다는 점을 염두에 둘 것.
